файлы) в рамках задачи «игровой 2D-движок поверх API `simulation.py`».

**Важно:** файл модели `simulation.py`, а также канонная документация
(`MODEL.md`, `README.md`, `FIX_HYPOTHESIS.md`) **ни разу не изменялись** — это зона
ответственности другого сотрудника. Все правки ниже касаются только слоя
визуализации/ввода `game_engine.py`.

## Детали изменений по коммитам

### 2. `4d7bee9` — Независимость от подсистемы шрифтов

**Проблема:** в pygame 2.6.x на Python 3.14 бинарный freetype собран нерабочим;
вся подсистема `pygame.font` недоступна (circular import `Font`). Движок падал
при инициализации, причём прежний `try/except` не спасал, так как падал сам
доступ к атрибуту `pygame.font`.

**Решение:**
- `_probe_font()` — безопасная проба шрифтов с явным `pygame.font.init()`; никогда
  не бросает исключений наружу. Если шрифт работает — штатный путь (кириллица в HUD).
- `BitmapText` — встроенный растровый шрифт 3×5 (латиница, цифры, пунктуация),
  рендерится только через `pygame.draw.rect/Surface`. При сломанном `pygame.font`
  движок автоматически переходит на него и НЕ падает. Три кегли (default/small/big)
  имитируются масштабом 3/2/4.
- `FontSet` — единый интерфейс (`.font/.font_s/.font_b`) для обоих режимов.
- `main()` при битом font печатает диагностику в stderr с инструкцией:
  `pip uninstall -y pygame && pip install pygame-ce`. В HUD показывается строка
  `FONT FALLBACK`.

**Проверка:** headless-тест с жёсткой имитацией бага (модуль `pygame.font` без
`Font`) — полный кадр рисуется, main() проходит end-to-end без падений; на
рабочем pygame-ce 2.5.8 native-шрифты и кириллица работают, fallback не включается.

### 3. `19ac13b` — Кликабельный интерфейс и чистая типографика

**Проблема:** «жму кнопки — реакции нет»; в тексте встречались битые юникод-глифы.

**Решение:**
- Кнопки START/PAUSE, STEP, SPEED, MODE, RESET сделаны кликабельными областями HUD
  с визуальной обратной связью (hover/press).
- Цифры 1–9 (выбор действия) работают всегда, автоматически включая ручной режим.
- Плитки действий видны постоянно; исправлено перекрытие зон кнопок и плиток,
  блокировавшее клики.
- Все спецсимволы заменены на ASCII/кириллицу/латиницу (стрелки → `->`, галочки →
  `[x]`, и т.п.).

### 4. `f6aeb17` — Консольное логирование для отладки

**Требование:** подробное логирование в консоль без записи в лог-файлы.

**Реализация:**
- Класс `_Logger`: вывод только в `stderr`, метки уровня (`INFO/DEBUG/WARN/ERROR`),
  относительная временная метка `t=секунды`.
- Уровни детализации через переменную окружения `GAME_LOG`: `0` (INFO+),
  `1`/`v` (DEBUG событий ввода/кадров), `vv` (полная трассировка каждого тика:
  состояния агентов, действия, результаты трансферов).
- Обёртки критических секций (импорты, проба шрифтов, игровой цикл): перехват
  исключений с печатью полного стека и автоматической остановкой симуляции
  (`paused=True`) вместо молчаливого падения.
- Стартовый дамп окружения: версия python, pygame/SDL, cwd, путь и mtime
  `simulation.py`, аргументы командной строки.

Пример запуска для отладки:
```bash
GAME_LOG=vv python game_engine.py 2> errors_console.txt
```

### 5. `c14a671` — Совместимость API модели + чистый лог событий

**Проблема (по логам пользователя):** `TypeError: RLAgent.form_intention() missing
1 required positional argument: 'rng'` — в свежей ревизии `simulation.py` сигнатура
изменилась на `form_intention(eps, rng)`; партия падала на первом тике после START.
Дополнительно лог засоряли сотни строк `MouseMotion`.

**Решение:**
- `_detect_form_intention_arity()` — при создании партии определяет арность метода
  через `inspect.signature` и вызывает корректно:
  - arity 3 (новая ревизия) → передаётся собственный `rng` движка;
  - arity 2 (старая ревизия) → прежний путь с временной изоляцией глобального `random`.
  Seed-детерминизм сохраняется в обоих случаях. Сбой интроспекции не роняет движок
  (откат на сигнатуру по умолчанию + WARN).
- `MOUSEMOTION` полностью исключён из лога; логируются только значимые события:
  клики по кнопкам/плиткам (координаты + результат), клавиши, QUIT/оконные события.

### 6. `89ec2a8` — Фикс рендера на float-полях новой модели

**Проблема:** в свежей ревизии `simulation.py` поля `commit.work` и `energy_pool`
стали `float`; рендер падал:
- `ValueError` при форматировании `E=%d` в панелях агентов и среды;
- `TypeError: 'float' object cannot be interpreted as an integer` в
  `draw_transfers` (pygame-ce требует целые координаты).

**Решение:** форматирование `%d` → `%4.0f` (2 места); целочисленное приведение
координат стрелок трансферов (`wdt/sx/tx`, наконечник); удалён мёртвый код.

### 7. `5acd3e5` — Автоподбор размера окна и Layout-класс

**Требование:** окно побольше, автоподбор разрешения от экрана, соотношение 12:9;
устранить перекрытия кнопок.

**Реализация:**
- `compute_window_size()` — подбирает размер окна 12:9 из доступного разрешения
  экрана (диапазон 1024x576 … 1920x1080), с fallback при недоступности display.
- Флаг `--fullscreen` / `-f`; переменная окружения `GAME_WINDOW=WxH` для ручного
  задания; поддержка `VIDEORESIZE` (масштабирование интерфейса пропорционально окну).
- Класс `Layout` — динамический расчёт непозиционированных вручную областей:
  арена, плитки действий, кнопки, график истории; константы пиксельной вёрстки
  заменены на вычисляемые геометрии.

### 8. `6b478fd` — Переработка HUD: три изолированных пространства

**Проблема:** после предыдущей итерации кнопки всё ещё перекрывались, график
статистики был расположен неудобно.

**Решение — экран разбит на 3 вертикальные колонки с внутренними секциями:**

- **Колонка A (слева, ~25% ширины) — метрики:**
  заголовок матча; карточки `RL agent`, `UtilityAI agent`, `Environment`,
  `Match status`. Длинные строки усекаются, содержимое клибуется по границам
  карточек.

- **Колонка B (центр) — сцена:**
  - B1 (верх): арена — автоматы Шмитта, стрелки трансферов, сообщения;
  - B2 (низ): полоса действий — сетка 2×4 кликабельных плиток + плашка `PICK`
    в последней клетке; сетка центрирована, текст центрируется в ячейках.

- **Колонка C (справа, ~25% ширины) — управление и статистика:**
  - C1: кнопки управления в сетке 4×2:
    `START | STEP` / `SPEED< | SPEED>` / `MODE | RESET` / `HELP | индикатор темпа`.
    Равные ячейки с фиксированным зазором — пересечения невозможны по построению;
  - C2: подпись состояния `RUN`/`PAUSE`/`PICK`;
  - C3 (остаток высоты): график force history с легендой внутри рамки.

**Гарантии целостности раскладки:**
- Секции каждой колонки режутся «дольней меркой» от краёв с гарантированными
  зазорами: `GAP=12` (между колонками), `VGAP=14` (между секциями),
  `CELL_GAP=8` (между ячейками сеток); при нехватке места секции пропорционально
  сжимаются.
- В `Layout` встроена самопроверка: колонки по X, секции по Y, вхождение кнопок и
  плиток в свои секции; при нарушении — предупреждение в лог.
- Разделители зон рисуются посередине зазоров (`_draw_zone_separators`).
- Справка F1 занимает секцию B2 поверх полосы действий.

**Обновлённые функции отрисовки:** `draw_panel`, `draw_action_bar` (+PICK-плашка),
`draw_buttons` (сетка; speed_rect — отдельная ячейка), `draw_history`, новая
`draw_caption`.

**Верификация:** геометрия проверена для окон 900×600, 1024×640, 1100×700,
1280×960, 1536×1152, 1920×1440 — ни одного пересечения кнопок между собой,
плиток между собой, кнопок с плитками/графиком/карточками; всё внутри окна
(`ALL LAYOUT CHECKS PASSED`).

Сопутствующее: в `.gitignore` добавлено исключение `*.bundle`; в репозиторий
помещён `game_engine_updates.bundle` (переносимый бандл ветки для доставки
изменений без доступа к remote).

## Управление (актуальная сводка)

| Действие | Клавиша | Альтернатива мышью |
|----------|---------|--------------------|
| Старт/пауза | Space | клик по кнопке START |
| Шаг тика | S / Right | клик по кнопке STEP |
| Темп +/- | [ и ] | клик SPEED< / SPEED> |
| Ручной/авто режим | M | клик по кнопке MODE или плитке действия |
| Выбор действия 1–7 | цифры | клик по плитке REST/FIRE/WATER/EARTH |
| Новая партия (reset) | R | клик по кнопке RESET |
| Справка | F1 / H | клик по кнопке HELP |
| Полный экран | — | флаг `--fullscreen` / `-f` |

Переменные окружения: `GAME_LOG` (детализация лога), `GAME_WINDOW` (WxH),
`SDL_VIDEODRIVER=dummy` (headless-прогон для автотестов).

## Известные ограничения / заметки

- Кириллица доступна только при рабочем `pygame.font`; при fallback используется
  растровый шрифт (латиница/ASCII). Рекомендуемый ремонт окружения:
  `pip uninstall -y pygame && pip install pygame-ce`.
- Пропорции колонок (`width_a` / `width_c`) — параметры `Layout`, легко меняются
  при необходимости.
- Push в внешний remote из рабочей среды невозможен (нет настроенного origin и
  учётных данных); доставка — через `git pull <bundle> main` или руками после
  настройки remote.
