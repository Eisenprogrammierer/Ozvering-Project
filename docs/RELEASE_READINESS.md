## 1. Методология оценки

Работа декомпозирована по четырём осям соответствия цели релиза:

* **A. Среда обучения** — контракты `ArenaEnv`/`CampaignEnv`, награды,
  self-play, оценка, чекпойнты, рандомизация домена;
* **B. Играбельность** — экраны (`view/`, `ui/`, арена), сохранение/загрузка,
  время/скорости, обратная связь игроку;
* **C. Модель мира** — открытые вопросы 4-2-1 (§7 `WORLD_CORE_MODEL.md`),
  баланс и калибровка;
* **D. Инженерная обвязка** — зависимости, CI, воспроизводимость, упаковка,
  документация пользователя.

Если не указано иное, число в колонке «чн» — **остаток трудоёмкости в
человеко-неделях** при одном разработчике, знакомом с кодовой базой. Это
порядок величины, а не бизнес-план. Закрытые пункты остаются в таблицах с
нулём, чтобы история решений не терялась.

## 5. Варианты скоупа релиза

* **MVP-релиз (12–18 человеко-недель):** ось A без A7 + B3–B8 + D4–D7. Цель «среда для
  обучения + игра» достигнута: обе среды работают, обучаемый агент в
  комплекте, игра запускается одной командой, собирается onedir-дистрибутив.
  C-ось и A7 — roadmap v2.
* **Полный релиз под идеальную цель (44–64 человеко-недели):** MVP + A7 + выборочное C
  (C2, C5) + закрытие §7. Верхняя граница — если A7 потребует переработки
  награды и повторной калибровки арены.
* **Релиз v2 «зрелый мир» (+22 человеко-недели):** полное закрытие C-оси после MVP.

Рекомендация: идти к MVP. C-ось не блокирует ни обучение, ни игру, а только
глубину симуляции; A7 без изменения награды упирается в потолок, который
и есть часть C.
