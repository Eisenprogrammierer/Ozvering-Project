# `organizations`

Справочник собран из docstrings и примечаний к переменным. Номера строк относятся к версии до очистки кода.

## `organizations/__init__.py`

### Модуль

Строка 1.

Аналитические организации-суперсистемы, runtime и генератор JSON-автоматов.

Пакет не импортирует pygame и не меняет канон ``simulation.py``/``warfare.py``.
Модель принимает население, выводит приоритетную потребность, масштаб, уровень
и экономику участия, а затем генерирует автомат для редактора ``automata/``.
``OrganizationRuntime`` опционально подключает тот же разбор к живым
персонажам ``warfare.Character``: социальный такт идёт после боя и меняет
только существующие потребности/мораль, а не добавляет метрики в ``Agent.state``.

## `organizations/__main__.py`

### Модуль

Строка 1.

CLI: ``python3 -m organizations``.

Без флагов печатает разбор четырёх эталонных сценариев. С ``--write`` пишет
JSON-автоматы в ``configs/automata/`` (или в ``--out``) для редактора
``automata``. С ``--json`` печатает один автомат целиком. С ``--runtime``
прогоняет эталонный warfare-сценарий с организацией и печатает её состояние.

## `organizations/model.py`

### Модуль

Строка 1.

Аналитическое ядро организаций-суперсистем.

Слой чистый: он не импортирует pygame, ``simulation`` или ``warfare``. На вход
подаётся население (участники, их потребности/энергия/сила и граф связей), на
выходе — разбор организации:

* приоритетная потребность как смесь приоритета массы и лидера;
* плотность связей, эффективный масштаб, уровень и ёмкость уровня;
* универсальные функции (порядок/смысл/снабжение/...), из которых выводится
  ярлык «государство», «церковь», «банда», «артель» и т.п.;
* экономика участия: желающие остаются, нежелающие выходят; если не осталось
  ни одного желающего, организация распадается.

### function `organization_level`

Строка 51.

```python
def organization_level(effective_count, threshold=165.0)
```

Уровень организации по эффективному числу участников.

    ``L = ceil(sqrt(N_eff / 165))``. Порог 165 — калибровочная точка, в
    которой координационная энтропия начинает расти быстрее силы лидера.
    Ёмкость уровня — ``165 * L**2``; отсюда пороги 165, 660, 1485, ...

### class `Member`

Строка 72.

Участник: потребности, энергия, сила и (необязательно) граф связей.

    ``needs`` — неудовлетворённость в ``0..1``. ``urgency`` — взвешенная
    личностью значимость для выбора приоритета; если не задана, совпадает с
    ``needs``. Для экономики участия используется именно ``needs``: личность
    влияет на то, *что* организация считает главным, а не на размер нужды.

## `organizations/needs.py`

### Модуль

Строка 1.

Канонические 16 потребностей и аналитические профили организаций.

Модуль не импортирует ``warfare``/``simulation``: это чистые данные слоя
организаций. Порядок ``NEEDS`` совпадает с ``warfare.NEEDS``; синхронность
проверяется тестом ``tests/test_organizations.py``.

Профили ниже — не шаблоны организаций. Это **семантические коэффициенты**
потребности: насколько она тяготеет к той или иной универсальной функции
(порядок, смысл, снабжение, статус, знание, забота, обмен). Сами организации
выводятся формулами из приоритета, масштаба и уровня, а не выбираются из
таблицы готовых классов.

## `organizations/runtime.py`

### Модуль

Строка 1.

Runtime-слой организаций: персонажи/отделения → живая суперсистема.

Аналитическое ядро (``organizations.model``) отвечает на вопрос «какая
организация выводится из этого среза». Runtime-слой делает срез живым:

* на каждом такте собирает ``Population`` из текущих потребностей, энергии,
  силы и связей персонажей;
* пересчитывает приоритет, масштаб, уровень и участие;
* применяет блага к потребностям, взносы — к усталости/голоду, риск
  принуждения — к страху/тревоге, легитимацию — к морали;
* ведёт фазу универсальной цепи (мобилизация → производство → распределение →
  принуждение/легитимация → воспроизводство);
* при отсутствии желающих распускает организацию.

Слой не меняет канон ``simulation.py`` и не добавляет новых метрик в
``Agent.state``. Он опционален: ``WarfareSimulation`` без организаций ведёт
себя ровно как раньше.

### class `OrganizationRuntime`

Строка 57.

Организация как живая суперсистема над персонажами/отделениями.

    ``detachments`` удобны для кампании: организация сама разворачивает их в
    персонажей и после эффектов обновляет психологию отделений. ``characters``
    — для точечной интеграции без отделений.

    Параметры эффектов намеренно мягкие: один такт не должен заменять бой или
    полностью закрывать потребности. Экономика участия уже посчитана ядром;
    runtime лишь транслирует её в существующие BDI-поля персонажа.
