# Стилевой слой общения

> **Статус:** текущая реализация. Полная история первого подхода,
> отвергнутые схемы и подробный прогресс D5.1–D5.4 — в
> [`history/CHAT_STYLES_PLAN_FULL.md`](history/CHAT_STYLES_PLAN_FULL.md).
> Диалог в целом — [`DIALOGUE_NLG.md`](DIALOGUE_NLG.md).

## 1. Принцип

Стиль — это **регистровый профиль реализатора**, а не постобработка
готовой строки. Ответ собирается из смысла, речевого акта и регистра;
`frames`/`prefix`/`suffix`/`closer` запрещены.

## 2. Данные

| Файл | Роль |
|---|---|
| `configs/dialogue/styles.json` | 8 стилей, schema 4 |
| `configs/dialogue/features.json` | измерения профиля |
| `configs/dialogue/style_context.json` | автовыбор регистра и приоритеты правил |

Новый стиль, маркер или правило добавляются JSON-ом. Python не содержит
списка стилей.

## 3. Автовыбор

`StyleEngine.resolve_for_context` учитывает по порядку:

1. явный выбор игрока;
2. отношения и союз;
3. полномочия и статус;
4. подсказку режима разговора (`style_hints`);
5. правило контекста;
6. стиль по умолчанию.

`StyleDecision` возвращает стиль, источник (`explicit`/`persona`/`rule`/
`hint`/`default`) и причину для UI.

## 4. Дискурс

- `comparison.json` — числовые и порядковые сравнения.
- `counterfactual.json` — контрфакты с whitelist отношений.
- `discourse.anaphora` — замена повторов имени внутри ответа.
- `discourse.connectives.mode` — связки `plain`/`clause`; при
  `reason_in_text` причина не дублируется.
- `pattern.topic` — тема и ремы в абзаце 4+ хода.

## 5. Ограничения

- Ручной выбор «дружеского» или «враждебного» тона убран: регистр
  вычисляется, игрок может только переопределить его явно.
- Изменения отношений и убеждений должны быть видны в следующем ответе;
  это проверяется интеграционным тестом.
- `avoid_recent` ограничен N ходами и не должен выбирать неожиданный
  регистр в длинном разговоре.
