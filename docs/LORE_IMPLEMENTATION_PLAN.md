## 0. Главный инвариант

**Сюжет не прописывается ни в коде, ни в данных. Сюжет — результат
симуляции.**

Авторская последовательность сцен остаётся сценарием, даже если лежит в
JSON. Поэтому для automata-кампаний запрещены `arc`, `win_scene`,
`lose_scene`, `variants`, `variant_by`, `choices` и любые слайды с
сюжетным текстом. Последовательность сцен такой кампании — только
`gameplay`.

Код не содержит сюжетных имён и веток «если это Империя, то…». Он умеет
только интерпретировать общий протокол состояния.

## 1. Схема

### 1.1. Структурированный журнал

`AutomataCampaign.narrative` — список фактов. Каждый факт фиксируется в
момент изменения состояния и не содержит готового текста:

```json
{
  "kind": "action",
  "turn": 7,
  "elapsed": 518400.0,
  "actor": "Империя",
  "actor_side": "red",
  "target": "Республика",
  "target_side": "blue",
  "action_id": "imperial_edict",
  "label": "Опубликовать имперский эдикт",
  "success": true,
  "essence": "legitimize",
  "form": "information",
  "assets": [
    {"scope": "self", "key": "legitimacy", "delta": 0.0026},
    {"scope": "target", "key": "legitimacy", "delta": -0.001}
  ],
  "integrity_delta": 0.0224,
  "morale_before": null,
  "morale_after": null,
  "morale_delta": 0.0,
  "needs": [],
  "relations": [],
  "organ_id": "justice",
  "character_id": "",
  "report_id": "",
  "magnitude": 0.0959
}
```

Журнал пополняют:

- работы (`kind: "action"`) — успех/провал, эссенция, форма, дельты;
- взаимодействия с органами (`"organ"`), автоматами (`"automaton"`) и
  персонажами (`"character"`);
- решения по докладам (`"report"`) — мораль, потребности, отношения.

Журнал входит в снимок кампании и переживает сохранение/загрузку.

### 1.2. Хроника

`campaign/chronicle.py` не знает кампаний и не содержит сюжетных строк.
Он:

- группирует соседние факты одного противостояния в эпизоды;
- считает значимость по модулю изменений состояния;
- собирает текст из полей записи;
- выбирает важнейшие эпизоды для ленты и финала.

### 1.3. Стартовая сводка и финал

`chronicle.briefing_slides(campaign)` собирает вводный слайд из состояния:
роль, веса счёта, пороги поражения, соперник, курс правящей подфракции и
предупреждение о риске.

`chronicle.ending_view(campaign)` вычисляет финал из конечного состояния:
исход, счёт, пороги, доминирующие подфракции, курс и решающие эпизоды.
Ни `win_scene`, ни `lose_scene` в данных не нужны.

### 1.4. UI

- Главная лента показывает хронику вместе с фоновыми вестями; дубликаты
  схлопываются.
- В шапке видны цель, курс правящей подфракции, прогресс, риск и полоса
  баланса прогресса.

## 3. Критерии приёмки

- `python -m campaign.content_lint` чист.
- `python -m campaign.dialogue.lint` чист.
- `configs/storylines/*_campaign.json` не содержат `arc`, `win_scene`,
  `lose_scene`, `variants`, `variant_by`, `choices`.
- `configs/storylines/*_campaign_scenes.json` содержат только
  `{"type": "gameplay"}`.
- `pytest tests/test_narrative_emergence.py` доказывает:
  - факт появляется из работы, а не из сцены;
  - текст хроники отсутствует в конфигах дословно;
  - разные прогоны дают разные эпизоды;
  - журнал переживает сохранение и загрузку;
  - финал содержит счёт и пороги из состояния;
  - шапка показывает курс, риск и хронику.
- Полный прогон перед коммитом.
