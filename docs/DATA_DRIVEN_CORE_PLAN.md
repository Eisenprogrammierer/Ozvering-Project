> сломано, здесь — как чинить. Ни один пункт не меняет контракт 16

>
> **Принцип порядка работ:** сначала дешёвые изменения с максимальным

## 0. Стратегия

### 0.1. Три технических решения, на которых держится план

1. **Один движок эффектов.** Сейчас эффекты размазаны: работы
   (`_apply_branch`), взаимодействия персонажей,
   `faction_state`-драйверы. Нужен единственный `campaign/effects.py`,
   который понимает декларативный словарь эффектов и применяется везде.
   Иначе каждый новый слой контента потребует новой Python-ветки.
   События в этот движок **не входят**: они ничего не применяют.
2. **Один движок условий.** Аналогично: `campaign/conditions.py` читает
   `requires`/`when` и умеет активы, потребности, черты, убеждения,
   намерения, органы, отношения, флаги, историю. `_asset_requirement_reason`
   становится одним из терминов, а не единственным.
3. **Один движок автоматов.** `campaign/state_machine.py` исполняет
   состояния/переходы/обработчики из JSON. Фракция, подфракция и орган —
   три конфигурации одного рантайма, а не три разных класса поведения.

### 0.2. События — ролевой слой, а не ядро

Это отдельный архитектурный контракт, действующий с этой сессии:

* **Событие ничего не производит.** У него нет `effects`, `apply`,
  `emit`. Состояние меняют работы, переходы автоматов и действия
  игрока.
* **Событие не порождается событием.** Очередь событий не является
  причиной состояния; событие не вызывает другое событие.
* **Событие только отражает процессы.** У него есть `conditions`
  (что видно), `visibility`, `weight`, `text`/`templates`. Это чтение,
  а не запись.
* **Следствие для плана.** В DSL эффектов нет `emit`; в P3 нет
  «применения эффектов события»; линтер отклоняет событие с `effects`;
  `_apply_story_effects` удалён.
* **Следствие для контента.** Событие описывает уже случившееся:
  «миф треснул» после работы, «канал закрыт» после санкции. Причиной
  остаётся работа или переход автомата.

### 0.3. Совместимость

* `schema: 1` остаётся валидным. Все новые поля опциональны; при
  отсутствии работают текущие значения по умолчанию.
* Загрузчики принимают оба формата эффектов: старый плоский
  `effects.self: {legitimacy: 0.02}` и новый
  `effects.self.assets: {legitimacy: 0.02}`.
* Снимок кампании получает `schema_version`; миграция — в
  `campaign/storage.py` (или эквиваленте), старые снимки читаются.
* Новые поля сохраняются в снимок; отсутствующие восстанавливаются из
  контента.

### 0.4. Что останется в Python навсегда

| Механика | Почему не JSON |
|---|---|
| Арифметика потребностей, спилловер, смерть | Численный закон модели; параметры — в JSON |
| Формула вероятности работы (`base/slope/defense`) | Математика; параметры — в JSON |
| Порядок фаз хода и бюджет действий | Контракт цикла |
| Сортировка/ранжирование предложений ИИ | Алгоритм; веса — в JSON |
| Разрешение ссылок и валидация | Интерпретатор данных |
| Детерминизм по seed | Контракт |
| Диалоговый интерпретатор | Контракт чтения/записи; данные — JSON |

Всё остальное — данные.

## 4. P2. Модель веры v2

**Статус (2026-11-14): реализовано в объёме `value/confidence/source/ttl`,
правил `object: required|forbidden` и свойств без объекта. Не реализованы
пока: `since`/`expires` как абсолютные метки, `value_type`/`default_value`,
`decay`/`ttl_turns` на предикате, инверсия на чтении, порог `value` в
условиях событий. Эти поля остаются целью следующих итераций P2, когда
появится общий такт старения.**

**Цель:** закрыть G-09. Убеждение перестаёт быть голой строкой.

### Схема `bdi.json`

`belief_predicates.<key>` расширяется:

```json
{
  "label": "считает законной",
  "kind": "property",
  "object": "forbidden",
  "value_type": "boolean",
  "default_value": 1.0,
  "decay": 0.0,
  "inverse": null,
  "symmetric": false
}
```

```json
{
  "label": "доверяет",
  "kind": "relation",
  "object": "required",
  "value_type": "scalar",
  "default_value": 1.0,
  "decay": 0.002,
  "ttl_turns": 12,
  "inverse": "trusted_by",
  "symmetric": false
}
```

### Код

| Файл | Изменение |
|---|---|
| `bdi.py:91-135` | `Belief`: `object: str = ""`, `value: float = 1.0`, `confidence: float = 1.0`, `source: str = ""`, `since: float = 0.0`, `expires: float \| None = None` |
| `bdi.py:227-370` | `BDIConfig` различает `kind`, проверяет `object` по правилу `required/forbidden`, валидирует `inverse`/`symmetric` |
| `bdi.py:485-535` | `believe/forget/beliefs_about/belief_value` учитывают `value`, `confidence`, `subject`, `object`, инверсию и симметрию |
| `bdi.py:678-...` | `tick` применяет `decay`/`ttl` к убеждениям и возвращает дельты |
| `warfare.py:333-352` | сеттер `beliefs` принимает и триплеты, и расширенные словари |

### Семантика

* `property` — `object` пуст; значение `value` (0..1) — сила веры.
* `relation` — `object` обязателен; `value` — сила связи.
* `belief_value(predicate, subject=None)` — агрегат: max по
  `value × confidence` для подходящих триплетов.
* Инверсия: `A trusts B` автоматически даёт `B trusted_by A` при чтении
  (не при записи — чтобы не плодить дубликаты).
* `negate` в условиях сравнивает `value` с порогом, а не только наличие.

### Тесты

* Свойство без объекта валидно; свойство с объектом — ошибка.
* Отношение без объекта — ошибка.
* Инверсия и симметрия читаются корректно.
* TTL/decay уменьшают `value` и удаляют истёкшие.
* Старые триплеты из сейвов читаются с `value=1.0`.

## 5. P3. Единый движок эффектов

**Статус (2026-11-14): закрыто в `campaign/effects.py` и подключено к
`_apply_branch`. Поддержаны `self`/`target`, `assets`, `needs`, `traits`,
`conditions`, `beliefs.add/remove`, `intentions.push/clear`, `organs`,
`flags` и старый плоский формат. `relations` распознаётся, но отложена
до P8 и не превращается в актив. Линтер принимает новый набор ключей.**

**Цель:** закрыть G-03 и G-08 (запись). Один словарь эффектов для работ,
взаимодействий, событий, сюжета, состояний автоматов.

### Новый модуль `campaign/effects.py`

```python
def apply_effects(campaign, scope, effects, *, scale=1.0, source=None):
    """Применить декларативный словарь эффектов к выбранной области."""
```

Области (`scope`): `self`, `target`, `characters`, `faction`,
`subfactions`, `organ:<id>`, `all_characters`, `leader`.

### Схема эффектов

```json
{
  "assets": {"legitimacy": 0.02, "myth": -0.03},
  "needs": {"fear": 0.05},
  "traits": {"loyalty": -0.02},
  "conditions": {"wound": 0.1},
  "beliefs": {
    "add": [
      {"predicate": "is_legitimate", "object": "", "value": 0.4, "source": "edict"},
      {"predicate": "betrayed_by", "object": "faction.republic", "value": 0.8}
    ],
    "remove": [
      {"predicate": "trusts", "object": "faction.empire"}
    ]
  },
  "intentions": {
    "push": [{"target": "faction.republic", "essence": "coerce"}],
    "clear": false
  },
  "organs": {
    "panzerwaffe": {"integrity": -0.15, "state": "strained"}
  },
  "relations": {
    "faction.republic": {"fear": 0.1, "trust": -0.05}
  },
  "flags": {"amnesty_offered": true, "purge_turn": 7}
}
```

Правила:

* Все числа аддитивны и умножаются на `scale` (текущий
  `model.effect_scale`).
* `beliefs.add` идемпотентен по `(subject, predicate, object)`: повторное
  добавление обновляет `value` (max или сумма — параметр `mode`).
* `organs.<id>` без `state` меняет только целостность.
* Неизвестный ключ эффекта — ошибка линтера (P0), в рантайме —
  предупреждение в лог и пропуск.
* В DSL **нет `emit`**: событие не является эффектом и не ставится в
  очередь. Если нужен рассказ о произошедшем, его подхватывает слой
  отражения по своим `conditions`.

### Совместимость

Старый формат:

```json
"effects": {
  "self": {"legitimacy": 0.02},
  "target": {"cohesion": -0.05},
  "needs": {"target": {"fear": 0.02}}
}
```

интерпретируется как:

```json
"effects": {
  "self": {"assets": {"legitimacy": 0.02}},
  "target": {"assets": {"cohesion": -0.05}},
  "target": {"needs": {"fear": 0.02}}
}
```

Нормализация — в загрузчике (`campaign/preset.py` или отдельном
`campaign/schema.py`), чтобы рантайм видел только новый формат.

### Код

| Файл | Изменение |
|---|---|
| `campaign/effects.py` | новый модуль; единственная точка записи |
| `campaign/automata.py:1969-1987` | `_apply_branch` → тонкая обёртка над `apply_effects` |
| `campaign/automata.py` (взаимодействия персонажей) | применять `effects` через тот же движок |
| `campaign/automata.py` (`_advance_story_events`) | **не** вызывает эффекты: событие только фиксируется в журнале |
| `campaign/faction_state.py:296-370` | драйверы выразить как эффекты или оставить как оптимизацию |

### Тесты

* Работа добавляет убеждение и оно видно в снимке.
* Работа снимает убеждение.
* `needs` применяются к цели, а не к действующему.
* `organs` меняет целостность нужного органа.
* `flags` участвуют в условиях (после P4).
* Событие с `effects` отклоняется линтером; `_advance_story_events`
  не меняет состояние.
* Старый формат даёт те же числа, что до рефакторинга.

### Код

score = ai_priority * w
      + essence_match(work, leader.intentions) * intention_w
      + belief_value(work.belief_bonus) * belief_w

      + relation_score(target) * relation_w

Все веса — из JSON; отсутствующие термы = 0.

2. Прогнать полный набор (`pytest -q`) и зафиксировать зелёный снимок;
   текущий снимок — 1252 теста.
3. Затем — **D6.2c** (`predicate_relations`), **D6.2b** («то»-клауза),
   **D6.2d** (условия/уступки/косвенная речь) и тесты D3.2/D6.2a.
4. Параллельно — **P0** (`configs/schemas/`) и **P7** (ИИ из данных).
5. Контент (`CONTENT_PLAN_LORE.md`) писать параллельно, подключать
   после P3–P4.
