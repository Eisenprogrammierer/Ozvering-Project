## P0. Баланс на дне: PRESSER доминирует TIMING (F0=10)

* **Наблюдение.** CI-тест (`experiments/exp_balance_ci.py`, детерминирован по seed)
  на дне даёт PRESSER/TIMING = **15:5 (0.75)** при пороге `DOM_LIMIT=0.65` →
  код возврата **1**; на плато (F0=30) баланс держится (7:13, роли симметричны).
* **Почему отложено.** Это ограничение **структуры** экономики, а не подбор одного
  скаляра: линейное трение `K_EFFECT` даёт «нож-лезвие» — при `0.70…0.95` дно
  стагнирует (партии не решаются), при `1.0` чистых потерь нет вовсе; устойчивого
  среднего режима нет. По согласованию параметры **не менялись**.
* **Задокументировано.** [`MODEL.md`](MODEL.md) §15.1 и §15.6;
  [`BASELINE.md`](BASELINE.md) → «Баланс» и «Калибровка экономики».
* **Предлагаемый шаг.** Ввести убывающую/ограниченную отдачу удара при
  `K_EFFECT > 0`, чтобы появился устойчивый средний режим; затем расширить набор
  активных стратегий в CI и ужать пороги.
* **Критерий готовности.** `python3 experiments/exp_balance_ci.py` возвращает **0**
  на **обоих** уровнях `F0 ∈ {10, 30}`.

## P0. Контрольное плечо `with_env=False` вырождается в истощение

* **Наблюдение.** Без среды-автомата канон решается лишь ~3/10 партий (в контроле
  `run_batch` `with_env=False`: RL 3 / AI 0 / без решения 7), медиана силы → 1 —
  «позиционная война на истощение».
* **Почему отложено.** То же структурное ограничение `K_EFFECT`, что и выше;
  плечо оставлено **намеренно жёстким контролем** (не целевой сценарий).
* **Задокументировано.** [`BASELINE.md`](BASELINE.md) → «Калибровка экономики»,
  «Известные ограничения» п. 1.
* **Предлагаемый шаг.** Тот же структурный фикс отдачи удара (общий с P0 №1);
  после — пересмотреть роль контрольного плеча.
* **Критерий готовности.** Контроль без среды перестаёт вырождаться в `F→1`
  без потери здоровья канона `with_env=True`.

## P1. Профиль как возможная «скрытая конституция» (§15.2)

* **Суть.** «Характер» автомата задаётся одним скаляром `p` (`PROFILES`),
  умножающим существующие константы. Открыто: не является ли это скрытой
  конституцией («нечестным характером», влияющим на исход помимо наблюдаемой
  игры), несмотря на косвенную наблюдаемость (`opp_decay_guess`).
* **Почему отложено.** Требует методологического решения, а не правки кода; в
  этапы 0–4 не входило.
* **Задокументировано.** [`MODEL.md`](MODEL.md) §2а и §15.2.
* **Предлагаемый шаг.** Протокол эксперимента: сравнивать профильные дуэли с
  «раскрытыми» профилями (наблюдаемость снизу вверх) и оценивать, объясняются ли
  исходы только наблюдаемыми величинами.

## P1. Рекурсивная ротация «погоды» для иерархий глубины ≥ 2 (§15.4)

* **Суть.** `Environment.rotate_defense` ротирует только **прямых членов-суперсистем**
  (`Environment`, один ярус вниз): защита («погода») суперсистем глубины ≥ 2 не
  ротируется.
* **Почему отложено.** Функциональная доработка; в текущих проверках (раздел 14)
  иерархии глубины ≥ 2 не задействованы.
* **Задокументировано.** [`MODEL.md`](MODEL.md) §15.4.
* **Предлагаемый шаг.** Сделать ротацию рекурсивной (обход вглубь по `members`),
  сохранив самоподобие кодекса; добавить проверку в `exp_hierarchy.py`.
* **Критерий готовности.** Защита всех ярусов ротируется; `exp_hierarchy`
  подтверждает идентичность распределений на глубине ≥ 2.
