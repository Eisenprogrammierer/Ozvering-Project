## P0. Баланс при контекстном типе — ЗАКРЫТО (CI и канон)

* **Что сделано.** Возвращена **остаточная неопределённость типа**: рецептивный тип
  = `TYPES[(context_base + hidden) mod 3]`, где `context_base` наблюдаема, а
  `hidden` (выходная фаза адресата данного такта) — нет (одновременные ходы).
  Обработчики маргинализуют по типам под равномерным априором, а `strategies.timing`
  стал типо-безразличным. Результат: **CI-критерий выполняется** на обоих уровнях
  (`exp_balance_ci.py` → код возврата **0**; доминирование ≤ 0.60 при пороге 0.65),
  тогда как без остаточной неопределённости TIMING доминировал слепой PRESSER
  (0.85/0.90).
* **Что сделано (канон).** Устранены **две структурные причины** winner-take-all —
  и обе оказались дефектами сравнения, а не типа энергии:
  1. **Физическое состояние RL переносилось между партиями** (сила, пул, вход,
     `beliefs`), хотя переносить задумано только обучение (Q-таблицу). Проигравший
     стартовал следующую партию у дна силы, победитель — усиленным: исход решал
     ПОРЯДОК партий. Теперь `play_game` сбрасывает состояние сторон
     (`Agent.reset_state`), переносится только Q.
  2. **eps anneal'ился по такту ВНУТРИ партии** (`1.0 - step/300`) и сбрасывался
     каждую партию. Партии коротки (~20–60 тактов до захвата), поэтому агент почти
     всю игру играл случайно и никогда не эксплуатировал выученное. Теперь eps
     anneal'ится по ОБЩЕМУ опыту (`RLAgent.epsilon`), а не по такту партии.
  Результат: канон RL-vs-UtilityAI больше **не** winner-take-all — RL берёт партии
  на КАЖДОМ блоке seed (детерминированно; `experiments/exp_rl_strength.py`; 27/110
  против UtilityAI). Остаточное преимущество model-based UtilityAI признано
  **дефектом по цели проекта** (конкурентоспособность RL — цель, п. A5 ревью;
  см. P1 ниже) — прежняя формулировка «свойство табличного RL» снята.
* **UtilityAI не доминирует.** Скриптовый PRESSER обыгрывает его (12/20), а
  PASSIVE/TIMING сводят дуэль вничью (захвата нет): слабость была в RL, не в модели.
* **Задокументировано.** [`MODEL.md`](MODEL.md) §2 и §15.1;
  [`BASELINE.md`](BASELINE.md) → «Контекстный тип», «Баланс», «Сила RL».
* **Критерий готовности (CI).** `python3 experiments/exp_balance_ci.py` → **0** на
  **обоих** `F0 ∈ {10, 30}` — **достигнут**.
* **Критерий готовности (канон).** RL-vs-UtilityAI перестаёт быть winner-take-all
  при скрытой фазе типа — **достигнут** (`exp_rl_strength.py`).

## P0. Экономика обмена: «нож-лезвие» `K_EFFECT` — ЗАКРЫТО (снято архитектурой)

* **Исходное наблюдение (до архитектурного этапа).** Линейное трение `K_EFFECT`
  давало «нож-лезвие»: при `0.70…0.95` контроль без среды (`with_env=False`)
  стагнировал (`F→1`, партии не решались), при `1.0` чистых потерь нет вовсе;
  устойчивого среднего режима одним скаляром не было.
* **Переизмерено после P0 №1** (`experiments/exp_keffect_regime.py`, детерминированно):
  - исходный симптом **не воспроизводится** ни для какого `K>0`: контроль решается
    на всём `K∈[0.4,1.0]` (проигравший прижат к `F≈3–11`, но партия ЗАВЕРШАЕТСЯ
    захватом); ничьи в скриптовой матрице — структурные (обе стороны в покое), а не
    «истощение в ничью»;
  - канон держит **устойчивый средний режим**: при `K∈[0.4,0.9]` RL берёт 2–3 партии
    из 20; вырождение лишь при `K=1.0` (снова winner-take-all).
* **Остаточная чувствительность баланса (не исходный симптом).** В скриптовом
  CI-критерии на плато `F0=30` баланс держится в узком окне `K∈[0.6,0.7]`; при
  `K≥0.8` TIMING доминирует PRESSER (>0.65). На дне `F0=10` баланс держится при всех
  `K`. То есть «нож-лезвие» переродилось в чувствительность баланса к `K` на плато.
* **Структурный прототип (порог `W0`) больше не инертен, но нож-лезвие баланса им не
  лечится.** При `N=40` и каноническом `K=0.70` вариант `W0=4` ПРОВАЛИВАЕТ критерий
  на `F0=30` (`TIMING>PRESSER=0.68`) и возвращает winner-take-all в каноне
  (`env=True`: RL 0/10). Поэтому фикс **не добавляется** (по ТРИЗ: функции, которой
  нет, нет и нужды; исходный симптом снят архитектурой).
* **Задокументировано.** [`MODEL.md`](MODEL.md) §15.6;
  [`BASELINE.md`](BASELINE.md) → «Нож-лезвие `K_EFFECT`»;
  `experiments/exp_keffect_regime.py`.
* **Критерий готовности.** Устойчивый средний режим при `K_EFFECT>0`; контроль без
  среды не вырождается; критерий баланса на обоих `F0` — **достигнут** (при
  каноническом `K=0.70`; исходный симптом снят архитектурой).

## P1. Профиль как возможная «скрытая конституция» (§15.2) — РЕШЕНО

* **Суть.** «Характер» автомата задаётся одним скаляром `p` (`PROFILES`),
  умножающим существующие константы. Вопрос: не является ли это скрытой
  конституцией («нечестным характером», влияющим на исход помимо наблюдаемой
  игры), несмотря на косвенную наблюдаемость (`opp_decay_guess`).
* **Решение — протокол наблюдаемости** (`experiments/exp_profile_constitution.py`):
  профильные дуэли сравниваются по двум осям — наблюдаемость (восстановление `p`
  из штатного канала `opp_decay_guess`) и решительность/вырожденность.
  - При `p ≤ 1` профиль **наблюдаем** (оценка `DECAY_ADOPT·p` на ≈93–97% тактов,
    ошибка ≤0.005). Он решителен (у `ZEALOT`/`ORTHODOX` половина канона —
    ничьи), но честно различим по наблюдаемой траектории `w_adopt` → **не скрытая
    конституция**. Выходной канал профиля (масштабирование тяжести захвата) удалён
    как инертный: партия завершается первым же захватом (пункт A7 ревью).
  - При `p > 1` профиль **вырожден** (`DECAY_ADOPT·p > 1` — входной закон
    перестаёт быть сжатием, `w_adopt` растёт без напора) и **не наблюдаем**
    (канал слеп на 100%: оценка строится по убыванию давления, которого нет) →
    скрытая конституция.
* **Вывод.** Допустимый диапазон профиля — **`p ≤ 1`**; ветвь `p > 1`
  **удалена из `PROFILES`** (прежние `PRAGMATIST`/`OPPORTUNIST`) — по ТРИЗ
  скрытой ветви не существует. Новых программных сущностей не введено: профиль
  остаётся одним скаляром, модифицирующим обработку.
* **Задокументировано.** [`MODEL.md`](MODEL.md) §2а и §15.2;
  [`BASELINE.md`](BASELINE.md) → «Профиль: наблюдаемость»;
  `experiments/exp_profile_constitution.py`.
* **Критерий готовности.** Методологическое решение принято (профиль не является
  скрытой конституцией в допустимом диапазоне) — **достигнут**.

## P1. Конкурентоспособность RL — ЦЕЛЬ (дефект: канон RL 1 / UtilityAI 9)

Решением ревью (2026-10-16, п. A5) конкурентоспособный RL **входит в цели
проекта**, поэтому канон `RL 1 / UtilityAI 9` — **дефект**, а не принятая норма
(прежняя формулировка «свойство табличного RL» снята).

Замер чувствительности (`experiments/exp_rl_sensitivity.py`, 30 партий на
конфигурацию): доля побед RL устойчиво в меньшинстве во всём разумном диапазоне
`EPS_*`/`alpha`/`gamma`/`discretize`; единственный заметный фактор — **горизонт
разведки** `EPS_DECAY_STEPS` (3000 → 13%; 6000 → 27%; 12000 → 27%); `EPS_MIN`,
`alpha`, `gamma` почти не влияют; грубая дискретизация чуть помогает (13% → 20%).

Уточняющий замер 2026-10-25 (`experiments/exp_p1_rl_boost.py`, 30 партий,
сквозное Q, `with_env=True`): канон 4/30 (13.3%); `EPS=6000` и `12000` — **8/30
(26.7%)**; `24000` — 4/30; `48000` — 7/30. Reward shaping **не помогает**:
`r=ΔF−0.25·ΔF_opp` → 6/30, литеральное `+0.25·ΔF_opp` → 5/30, бонус за успех →
4/30; комбинации лучших факторов ≤ 7/30. **Потолок табличного Q с `delta F` —
~27%**, то есть дефект не снимается подбором констант/награды.

Направления усиления (не реализовано; канон пока не менялся):

* длиннее горизонт разведки — частичный шаг, но только до ~27% и немонотонно;
* функция награды (сейчас `delta F` за такт) и учёт отдачи/возмездия — замеры
  показывают, что в текущей форме это не даёт >27%;
* **выход за табличный Q:** function approximation / обобщение, opponent
  modeling, pretrain или иной алгоритм — единственный путь к цели >50%;
* если горизонт всё же меняется, это меняет канон-пин `1/9/0` — нужно отдельное
  решение и новый baseline, а не тихая правка.

  `Environment` берётся их `member_output`). Новых переменных/функций нет —

  доминированию/контролям держится практически `K∈[0.4,0.75]` (точка `0.50` —
  ровно на пороге `0.65`), канонический `K=0.70` внутри с запасом `0.05`.
  Реальный отказ только при `K≥0.80` (`TIMING`/`EAGER` доминируют `PRESSER`,
  `0.70–0.72`); он не лечится `OFF_FRAC`/`GAIN_MAX` — граница определяется самим
  коэффициентом трения. Замеры — `experiments/exp_g1_keffect_window.py`
  (`N=12` + контроль `N=40`); [`BASELINE.md`](BASELINE.md) → «Баланс:
  `K_EFFECT`, профили, RL». Остаточный пункт `K≥0.8` — вне рабочей области,
  требует изменения core, а не подкрутки.
* **G2. Балансовая пригодность профилей `p<1` — ОТКРЫТО.** Уточнение замера
  (`experiments/exp_g2_profiles.py`, 20 партий на пару): `p<1` — не просто
  «половина ничьих», а **взаимное истощение до `F=1`** в self-play
  (`ZEALOT/ZEALOT`, `ORTHODOX/ORTHODOX` — 0/20 захватов) и **одностороннее
  защитное преимущество** в смешанных парах (`ZEALOT` 11W/0L/9D, `ORTHODOX`
  17W/2L/1D против `CANON`). Канал `OFF_FRAC/p` инертен (окно закрывается по
  `open_timer`); активен только `DECAY_ADOPT·p`. Компенсации: `OFF` не помогает;
  `DECAY·(0.5+0.5p)` не решает self-play; `DECAY·(0.85+0.15p)` даёт 16/20, но
  профиль почти косметический; полная нейтрализация `DECAY` возвращает канон.
  **Цель — либо явно переклассифицировать `p<1` в асимметричный
  «защитный/гандикапный» профиль, либо менять профильный канал/`open_timer` в
  core.** Измерения — `experiments/exp_g2_profiles.py`,
  `experiments/exp_profile_constitution.py`; [`BASELINE.md`](BASELINE.md) →
  «Профиль: наблюдаемость».

## Формулировки и калибровка (ревью 2026-10-16)

Перенесено из заметки ревью (раздел E). **F1 операционализирован** (см. ниже);
**F2–F4 закрыты измерениями/выводом** (см. ниже); **F5 снят контрактом лоссовой
наблюдаемости** (см. `DESIGN_ADVANCED.md` §1).

* **F1. Тезис «единый закон для трёх видов конкуренции» — РЕШЕНО
  (операционализировано).** В [`MODEL.md`](MODEL.md) (введение) тезис помечен как
  **намерение дизайна**, а не измеренный факт. Операционализация разделена по
  ролям (риск «двойного счёта свидетельств» — определение не выдаётся за
  доказательство):
  * **определение + сторож регрессий** — `tests/test_domain_audit.py`: в ядре
    взаимодействия (`resolve_attack`/`_apply_transfer`/`run_tick`/`play_game`)
    нет доменных идентификаторов/веток. Проходит по построению → **НЕ
    свидетельство**, а нормативная формулировка «одного закона» и защита от
    будущей доменной ветки.
  * **свидетельство** — `experiments/exp_domain_invariance.py` (код 0/1):
    доменный индекс как nuisance-параметр; **положительный контроль** мощности
    (заведомо нагруженный `K_EFFECT=1.0` и намеренно доменная ветка «для
    `informational` отправка бесплатна» ЗАМЕЧАЮТСЯ различителем) + **слепота**
    (неиспользуемый индекс инертен на всех `d`). «Мирное сосуществование» —
    вырожденный вход (`work = 0`) того же закона, отдельного домена не образует.
  * **Критерий готовности** — эксперимент даёт код возврата 0 (слепота при
    работоспособном различителе) — **достигнут**. Числа — в
    [`BASELINE.md`](BASELINE.md) → «Доменная инвариантность (F1)».
* **F2. Калибровка `BELIEF_NOISE=2` — ЗАКРЫТО измерением.** Сетка
  `BELIEF_NOISE ∈ {0,1,2,4,8}` (`experiments/exp_sensitivity_f2_f3.py`):
  канон 1/9/0 только при 2 и 4; 0 → 2/8/0, 1 → 4/6/0, 8 → 2/8/0. На плато
  F0=30 значения 1 и 8 дают max dominance 0.80 > 0.65. **Default 2 оставлен**
  как единственная точка (вместе с 4), где канон и плато не нарушены.
* **F3. Константы пула и покоя — ЗАКРЫТО измерением.** Нечувствительны:
  `MAX_WORK ∈ [100,400]`, `ENV_REST_CAP ∈ [5,20]`, `ENV_INCOME ∈ [1,3]`.
  Охранные границы: `E_MAX_MULT=2` → 0/0/10, `MIN_OUTPUT=1` → 0/0/10,
  `MIN_OUTPUT=4` → 4/6/0, `L_BASE=80` → 0/10/0, `L_STEP=5` → 2/8/0.
  **Defaults не менялись** — это границы применимости, а не свободные ручки;
  подробности — `BASELINE.md` → «Калибровка новых слоёв».
* **F4. Эвристика `rest_units -= cap / L_STEP` при захвате — РЕШЕНО
  (выведено).** Потолок покоя `L = L_BASE + L_STEP·rest_units` линеен, поэтому
  вычитание `cap/L_STEP` уменьшает `L` ровно на `cap` — столько же, сколько
  силы потерял проигравший. Захват масштабирует силу и потолок одинаково,
  сохраняя дефицит `L − F`; это согласовано с логистикой §5. Автотест —
  `tests/test_advanced.py::test_capture_scales_force_and_rest_ceiling_together`;
  пояснение — `MODEL.md` §6.
* **F5. Семантика среды-суперсистемы** (пункт A6 ревью). Двойное нагружение входа
  **измерено** (`experiments/exp_env_double_loading.py`): агрегат `member_output`
  пересчитывает уже учтённый прямой удар (≈0.94 от суммы ударов), входное давление
  среды +76%, окно 68%→77% тактов, исходы канона не меняются; возмездие тоже
  нагружает вход среды (≈22% прямого давления). **РЕШЕНО контрактом лоссовой
  наблюдаемости** (см. [`DESIGN_ADVANCED.md`](DESIGN_ADVANCED.md) §1): при
  `lossy=True` суперсистема получает единый агрегат канала, а `member_output` для
  участников дуэли не дублируется — двойное нагружение снимается; вниз идёт только
  публичное окно с задержкой. Остаются подвопросы: нужен ли среде содержательный
  «выход против агентов» кроме `ENV_BONUS`; почему `beliefs` среды жёстко
  зафиксированы (MVP не меняет). См. [`MODEL.md`](MODEL.md) §13–14, §16.

## P1. Лоссовая агрегация, LOD и энтропия смысла — MVP (2026-10-25)

Согласовано с автором (см. [`DESIGN_ADVANCED.md`](DESIGN_ADVANCED.md)); слои
вкатаны флагами **off** (`entropy=False`, `lossy=False`, LOD-1), канон `1/9/0`
не меняется. Реализация: `information.py`, `observability.py`, `lod.py`;
тесты — `tests/test_advanced.py`.

* **O1. Строгий публичный снимок суперсистемы — ЗАКРЫТО.**
  `Environment.public_snapshot()` отдаёт только `window`, `pressure_band`,
  `force_band`, `member_count`, `lossy`; identity/тип/точные `last_work` и
  метрики не раскрываются. `snapshot()` остаётся debug-only. Автотест —
  `tests/test_advanced.py::test_public_snapshot_hides_internals`;
* **E1. Дробная lineage-семантика энтропии — ЗАКРЫТО.** Линия начинается
  заново на старте партии (``reset_state``) и на захвате (``check_capture``);
  локальные счётчики/``H_local`` сбрасываются, ``H_cum`` сохраняется.
  Бюджет активных линий не нужен: у автомата один канал убеждений, а линия —
  это его временная граница, а не отдельный ресурс. Автотест —
  `tests/test_advanced.py::test_capture_starts_new_entropy_lineage_without_resetting_cum`.
* **E2. Энтропия по скрытой фазе/типу — ЗАКРЫТО решением.** Случайная величина
  энтропии — убеждения о наблюдаемом состоянии `(context_base, in_open)`, а не
  метка типа: тип в модели не хранится и не наблюдается (§2), posterior по
  `TYPES` был бы скрытой конституцией и дублировал бы `opp_ctx_base`. Демпфер
  уже ловит тип-эксплуатацию через наблюдаемое давление/окно; отдельный
  type-posterior не вводим.
* **L1. Онлайн-оценка ошибки LOD — ЗАКРЫТО.** ``lod.integrate_time`` возвращает
  ``False`` при дискретном событии внутри интервала (окно закрылось, сила
  упёрлась в гарантию жизни); ``run_duel_lod`` откатывает состояние и делает
  один LOD-1-такт. Это консервативный контроль ошибки без «эталонного» прогона
  и без второго канона. Автотесты — `test_integrate_time_reports_discrete_window_close`,
  `test_integrate_time_accepts_smooth_interval`.
* **L2. LOD для автономных подсред — ЗАКРЫТО решением (MVP).** Подсреда
  тикается рекурсивно на LOD-1: её закон содержит `ENV_INCOME` и
  `do_rest(chosen=False)` (логистика с постоянным притоком), для которых нет
  замкнутой формы; приближение дало бы ошибку агрегата, а выигрыш на текущих
  масштабах мал. LOD-2/3 остаются для дуэльного раннера ``run_duel_lod``;
  канон и подсреды — LOD-1.
* **C1. Калибровка новых констант — ЗАКРЫТО для раздельных слоёв.** Сетка
  (`experiments/exp_sensitivity_f2_f3.py`):
  `ENTROPY_SIGMA` держит канон в окне 0.10–0.15 (0.05/0.25 → 2/8/0,
  0.40 → 3/7/0); `OBS_RESOLUTION=1`/`4` и `OBS_DELAY=0`/`1` канон сохраняют,
  `2` — нет. Defaults `0.15`, `1`, `1` подтверждены. Совместный
  `entropy=True + lossy=True` ломает канон во всех проверенных комбинациях
  (дефолт → 4/6/0; лучшая `(0.15,4,1)` → 2/8/0) — **совместный режим остаётся
  экспериментальным, каноническая линия — оба флага off.** `LOD_WORK_THRESHOLD`
  теперь читается: `LodController.work_interval` выбирает LOD-2-интервал по
  работе; smoke 200 тактов не изменился. `LOD_ERROR_TOL` — резерв. Новый
  baseline — [`BASELINE.md`](BASELINE.md) → «Калибровка новых слоёв».
