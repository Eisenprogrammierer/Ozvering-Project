# Выжимка по проекту (код + документация)

> **Роль документа.** Сжатый конспект всего проекта — онтологии, законов, слоёв
> кода и текущего состояния — для быстрого входа и обзора. Это **не** источник
> истины: полная спецификация — [`MODEL.md`](MODEL.md), воспроизводимая база —
> [`BASELINE.md`](BASELINE.md), отложенные задачи — [`TODO.md`](TODO.md). При
> расхождении верны они. Все формулы ниже соответствуют `simulation.py`.

## 1. Что это

Иерархическая мультиагентная марковская игра с частичной наблюдаемостью,
структурированным символьным состоянием и обучением с подкреплением. Все
сущности — конечные автоматы на IPO-архитектуре (вход/обработка/выход/состояние);
персонажи дополнительно несут BDI-слой. Среда — «всеобъемлющий IPO-автомат»
(суперсистема того же кодекса). Войсковой слой `warfare.py` добавляет персонажей
с 16 потребностями и зачином черт, отделения-суперсистемы, станы, пассивные
приказы, заградотряды и подкрепления с задержкой (см. [`WARFARE.md`](WARFARE.md)).
Дизайн-принцип — ТРИЗ-редукция: «лучшая функция —
та, которой нет» (тип энергии не хранится, профиль — один скаляр, ротация защиты —
no-op, гипотеза «среда-пространство» удалена).

## 2. Онтология: ровно две метрики и работа

| Понятие | Роль | Поле кода |
|---|---|---|
| **Сила** `force` | накопленный ресурс, целевая функция; вещественная (дробь копится) | `Agent.force` |
| **Энергия** `energy_pool` | расходуемый запас, мера способности сообщать работу; пополняется `regen`, потолок `E_MAX_MULT·regen` | `Agent.energy_pool` |
| **Работа** `work` | сколько энергии сообщается за такт | `Agent.commit()` |
| **Состояние** `state` | единое хранилище: метрики + `last_act/last_work/w_adopt/in_open/open_timer/rest_units` | `Agent.state` |

Начало партии: `force=10`, `energy_pool=3`, `rest_units=0`, вход закрыт.
Рецептивного типа `defense` в `state` **нет** — это `@property` (функция
контекста, §4). Система **открыта**: закон сохранения силы не постулируется.
Информационная энтропия — **производная величина `beliefs`**, не третья метрика:
`state` не расширяется (см. §10).

## 3. Законы (канонические, `PARAMETERS`)

```python
# Энергия
regen        = max(1, floor(sqrt(force)))          # поток восстановления структуры
energy_pool  = min(energy_pool + regen, 3*regen)   # пополнение и потолок
work_legal   = min(work, pool, 200, max(2, force//4))   # три барьера выхода

# Вероятность успеха передачи (логистика от отношения мощностей + контр-тип)
mass  = min(att_work, 200) / max(dfn_work, 1)
p     = 0.6 / (1 + exp(-(ln(mass)*1.0 - 0.8·[контр-тип])))

# Восприимчивость входа адресата — триггер Шмитта с гистерезисом
ON(F)  = max(6, 0.25·F)          # накопленное давление >= ON => окно OPEN, TTL=8
OFF(F) = (0.4/p)·ON(F)           # давление ниже OFF => окно закрыто
w_adopt *= 0.95·p                # «заживление» (профильная скорость остывания)

# Экономика обмена (resolve_attack, шаги 1-6)
cost      = 0.2·w                                  # цена работы — сгорает всегда
_gain     = w·m·(1.2 если вход открыт, иначе 0.05) # m — контр-множитель MULT
loss_dfn  = w − 0.7·w = 0.3·w                       # чистая потеря (трение K_EFFECT)
hock_pool = 0.25·tr                                 # структурный шок пула адресата
retaliate = 0.5·w, дальше по тому же закону         # возмездие, без контр-возмездия

# Покой (логистика с потолком, растущим только от труда)
rest_gain = 8·(E/L)·(1 − E/L),  E = force − 1,  L = 60 + 10·rest_units
# осознанный покой = полная прибыль, режим покоя = 0.5·rest_gain

# Поражение — устойчивое доминирование
dominates(A,B) ⇔ A.pool >= 1.5·B.pool И A.force > B.force   # 20 тактов подряд
# затем перетекает 0.10·force проигравшего (×2, если его вход открыт)
```

Тип энергии — **контекстная фаза**, не валюта: `defense = TYPES[(context_base + hidden) mod 3]`,
где `context_base` наблюдаема (напор/окно/пул), а `hidden` — выходная фаза адресата
текущего такта, противнику недоступна (одновременные ходы) — **остаточная
неопределённость типа**. Наблюдатель берёт равномерный (максимально-энтропийный)
априор и маргинализует по трём типам. Контр-цикл `WATER>FIRE>EARTH>WATER` (×3).

Профиль (`PROFILES`): один скаляр `p ≤ 1`, множит существующие константы входа
(`DECAY_ADOPT·p`, `OFF_FRAC/p`). `ZEALOT=0.7`, `ORTHODOX=0.85`, `CANON=1.0`.
Ветвь `p > 1` удалена (вырождена и не наблюдаема). Профиль не наблюдается напрямую,
но восстанавливается из траектории `w_adopt` (канал `opp_decay_guess`).

## 4. Протокол такта (`run_tick`)

```
sense(противник) → rotate_defense (no-op) → upkeep → tick_energy → tick_input_state
→ намерения (RL: ε-greedy; Utility: argmax U) → рефлекс голода → commit (списание пула)
→ resolve_attack(A→B) → resolve_attack(B→A) → [learn(RL)] → check_capture
```
Порядок фиксирован; обе стороны зеркальны, оба удара — по одному закону. Шаги
наблюдения/тактовки/намерений/передачи вынесены в **единую** `simulation.run_tick`,
которую переиспользуют канон (`play_game`) и дуэли экспериментов
(`strategies.duel`), чтобы порядок не расходился. TD-обучение RL и `check_capture`
остаются у вызывающего. `with_env=True` добавляет такт среды тем же протоколом.

## 5. Агенты

* **`UtilityAI`** — заскриптованный BDI без обучения: перебор действий по
  `U(action) = отдача − цена − ожидаемое возмездие` (модель отдачи — тот же закон,
  что в среде, плюс опционная надбавка `0.10·progress` за «покупку окна»).
* **`RLAgent`** — табличный Q-learning: `s'` — 7 дискретизированных компонент
  beliefs (свой/чужой пул, тип атаки, угроза, напор, O/C, `opp_ctx_base`);
  `ε` anneal'ится по **общему** опыту (`EPS 1.0→0.05` за 3000 шагов), α=0.3, γ=0.9.
  Между партиями переносится **только Q-таблица**; физическое состояние
  сбрасывается (`Agent.reset_state`) — иначе исход зависел бы от порядка партий.

## 6. Среда и иерархия

`Environment` наследует `Agent` — весь кодекс (Шмитт, логистика, покой, upkeep)
реализован унаследованными обработчиками; новых переменных состояния нет.
Её вход нагружается всякой передачей; открытое окно даёт адресанту надбавку
`ENV_BONUS=0.25`; автономный доход `ENV_INCOME=2` ограничен потолком покоя, рост
`rest_units` от чужого труда капнут `ENV_REST_CAP=10` (иначе `ON(F)` уползал вверх
и окно закрывалось навсегда).

Иерархия: `members` — список `Agent`/`Environment`, композиция рекурсивна.
Агрегат `member_output` рекурсивно суммирует труд членов и подаётся на вход
суперсистемы (эмерджентный порог Шмитта над суммой). Канон нагружает вход
среды дважды (прямой удар + агрегат) — измерено в
`experiments/exp_env_double_loading.py`; исходы канона не меняются. Контракт
`lossy=True` снимает двойное нагружение: суперсистема получает единый агрегат
канала, а вниз идёт только публичное окно с задержкой (§10).

## 9. Статус и открытые задачи

* **Канон** (`run_batch(10)`, пин регрессии): `RL 1 / UtilityAI 9 / без захвата 0` —
  детерминирован, не зависит от `PYTHONHASHSEED`.
* **Кампанийный слой** (`view/`) не меняет канон: проекции рот выводятся из
  позиций и фронта (в т.ч. радиально при окружении), логистические операции
  масштабируются по числу целей, смерть командира при `health >= 1.0` служит
  условием поражения. Легаси-стихии убраны только из игрового UI
  (`ATTACK`, фазы `A/B/C`); внутренние имена `simulation.py` сохранены.
* **Баланс** (`exp_balance_ci.py`, 40 seed): критерий **выполнен** (rc=0);
  доминирование ≤ 0.60 при пороге 0.65, роли симметричны.
* **Открыто (дефекты калибровки, `TODO.md`):**
  * **G2** — профили `p<1`: self-play истощается до `F=1`, смешанные пары дают
    одностороннее защитное преимущество; компенсации либо инертны, либо почти
    стирают профиль;
  * **P1** — конкурентоспособность RL: потолок табличного Q без изменения core —
    ~27% (8/30), reward shaping не помогает; нужен выход за табличный Q.
* **G1 закрыт:** «узкое окно `K_EFFECT`» на `N=40` не воспроизводится — баланс
  держится `K∈[0.4,0.75]`, канон `K=0.70` внутри; остаточный `K≥0.8` — вне
  рабочей области.
* **Закрыто измерениями/решением (2026-10-25):**
  * **F2** — `BELIEF_NOISE=2` подтверждён сеткой; **F3** — defaults и границы
    применимости зафиксированы; **F4** — `rest_units -= cap/L_STEP` выведен как
    инвариант сохранения дефицита `L−F`;
  * **F5** — снят контрактом лоссовой наблюдаемости (§10); остаются подвопросы
    о содержательном выходе среды и её `beliefs`;
  * **O1** — `Environment.public_snapshot()`; **E1** — линия на захват при
    сохранении `H_cum`; **E2** — отклонена (энтропия по наблюдаемым убеждениям,
    не по скрытой метке); **L1** — онлайн-контроль интервала + откат на LOD-1;
    **L2** — подсреды остаются LOD-1 (нет замкнутой формы с `ENV_INCOME`);
    **C1** — defaults раздельных слоёв подтверждены, совместный режим вне канона.
* **Уже снято архитектурой:** стагнация без среды («нож-лезвие» `K_EFFECT`),
  winner-take-all канона, отклонение `expected_retaliation`, конверсия типов,
  рекурсивная ротация. Историчность артефактов — в `docs/history/`.

## 10. Новые слои (MVP, флаги off)

Три доработки вкатаны **выключенными по умолчанию**, поэтому канон `1/9/0`
не меняется. Полные решения — [`DESIGN_ADVANCED.md`](DESIGN_ADVANCED.md).

| Слой | Флаг | Что делает | Ограничение MVP |
|---|---|---|---|
| Лоссовая агрегация | `lossy=True` | вверх — `Observation` (агрегат работы, без identity/типа/тайминга), вниз — публичное окно с задержкой; снимает двойное нагружение F5 | `snapshot()` — debug; `public_snapshot()` — контракт |
| LOD | `lod.run_duel_lod` | LOD-1 событийный, LOD-2 работа + аналитика времени, LOD-3 mean-field с fallback | канон `play_game` — LOD-1; ошибка интервала ловится откатом, а не точным эталоном |
| Энтропия смысла | `entropy=True` | `H` по 4 корзинам убеждений, `H_cum`-ratchet + lineage, тяжёлохвостый мультипликативный шум только на `beliefs`; демпфер опциона `1 - noise_floor` | линия = партия + захват; распределение по наблюдаемым корзинам |

Запуск с новыми слоями:

```bash
python3 -c "import simulation as S; S.run_batch(10, entropy=True, lossy=True)"
python3 -c "import simulation as S, lod, random; ..."   # см. tests/test_advanced.py
```

Проверки контрактов — `tests/test_advanced.py` (детерминизм, монотонность `H`,
«нет отката», гистерезис, квантование/задержка, LOD-эквивалентность в допуске,
флаги off = канон). Чистая логика RTS-поля — `tests/test_battlefield.py`
(изометрия, движение/контакт, приказы, диалоги).
