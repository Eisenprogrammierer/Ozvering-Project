# UI.md — сценный (2-D экранный) слой

Документ описывает **традиционную игровую оболочку** Ozvering-Project: экраны
(меню, настройки, сохранения, нарратив, игровое поле) поверх слоя наблюдения за
партией. Слой живёт в пакете [`ui/`](../ui) и **не изменяет модель**:
активные сцены работают через `core41`, легаси-канон `simulation.py` не
затрагивается.

Сфера ответственности: **экраны, кнопки, нарратив, метрики и система
сохранений**. Персонажи, локации, 2-D арт и 3-D сцены — отдельные задачи, в этот
слой не входят (ниже — «Плейсхолдеры»).

## Запуск

```bash
pip install pygame-ce
python3 main.py               # единая точка входа: игра (старт — главное меню)
python3 main.py --view        # кампанийный интерфейс view (лагерь + RTS-карта)
python3 main.py --fullscreen  # (или -f) полноэкранный режим
python3 main.py --arena       # арена отдельно (автономный game_engine)
python3 main.py --interaction # экран взаимодействий (объект → действие → исход)
python3 main.py --checkpoint saves/bdi.json  # BDI-политика в активных сценах
python3 main.py --health-factors aging=1.5,illness=2  # множители здоровья
python3 main.py --sickness 0.5                       # начальная болезнь 0..1
python3 main.py --speed 4                     # 1x/2x/4x/8x/16x
python3 main.py --no-auto-pause               # без авто-паузы
python3 -m ui --scene game    # сразу открыть экран игры (отладка)
```

Кампанийный UI-каркас `view/` (лагерные сцены, интерактивная 2-D
изометрическая RTS-карта, приказы, документы и нарратив) запускается отдельно
через `python3 main.py --view`; его состояние строится на `warfare.py`, а не на
`simulation.py`. Подробности — [`CAMPAIGN_UI.md`](CAMPAIGN_UI.md).

`game_engine.py` по-прежнему запускается автономно (`python3 game_engine.py`) —
это прежний одиночный экран «арена + HUD». Сценный слой встраивает тот же
экран как сцену `game`; см. раздел «Встраивание» ниже.

## Карта экранов

| Экран | Модуль | Назначение |
|-------|--------|-----------|
| Главное меню | `ui/scenes/menu.py` | Поле боя (RTS), Взаимодействие, Новая партия, Продолжить (автосейв), Загрузить, Настройки, Об игре, Выход |
| Настройки | `ui/scenes/settings.py` | Полный экран, автосохранение, язык, громкости, скорость текста |
| Сохранения | `ui/scenes/saves.py` | Слоты автосейва и ручные 1–3: загрузить/сохранить/удалить |
| Нарратив | `ui/scenes/narrative.py` | Страницы вступления (плейсхолдер-иллюстрация + текст) |
| Игровое поле | `ui/scenes/game.py` | Обёртка над `game_engine.GameApp` (арена + HUD на `core41`) |
| Поле боя (RTS) | `ui/scenes/battlefield.py` | Изометрическая сетка, приказы, контакт, цель, ролевые диалоги |
| Взаимодействия | `ui/scenes/interaction.py` | Три панели: объекты, действия, шумные исходы; доменно-нейтральный каркас |
| Пауза | `ui/scenes/pause.py` | Оверлей поверх партии: Продолжить, Сохранить, Настройки, Меню |
| Об игре | `ui/scenes/about.py` | Сведения о проекте и подсказки по управлению |

`ui/battlefield.py` — чистая логика стратегической партии без pygame (сетка,
юниты, приказы, диалоги); её можно тестировать без GUI. `ui/scenes/battlefield.py`
только рисует и раздаёт ввод. Бой считается `core41.run_duel_tick`, поэтому
активная сцена не зависит от типизированной энергии легаси `simulation.py`.

Навигация: мышь (клик = клавиша); в партии — клавиши движка (`SPACE`, `TAB`,
`+`/`-` или стрелки, `M`, `1..6`, `R`, `F1/H`); `ESC` в партии открывает
паузу, `F11` — полный экран в любом экране. Скорости — пауза, `1x`, `2x`,
`4x`, `8x`, `16x`; авто-пауза срабатывает на критическом здоровье и
завершении партии (`--no-auto-pause` отключает). Клавиатурная навигация по
меню — задел на будущее.
На стратегическом поле: ЛКМ — выбор, ПКМ — движение, `1` — единая атака,
`R` — покой, `T` — лечение, `H` — держать, `Space` — ход, `Tab` — выбор
стороны, `F1` — справка.

## Архитектура

```
ui/
  __init__.py        # не импортирует pygame (save/content доступны без GUI)
  theme.py           # палитра, метрики, рисование панелей/плейсхолдеров
  widgets.py         # Button / Toggle / Slider / Label / Placeholder
  save.py            # SaveManager: настройки и слоты (JSON, атомарная запись)
  content.py         # нарратив и тексты (двуязычно, ru/en)
  scene.py           # Scene (базовый класс) + SceneManager (стек экранов)
  app.py             # App: окно, шрифты, главный цикл, роутинг, настройки
  scenes/            # конкретные экраны (см. таблицу выше)
  __main__.py        # точка входа `python -m ui`
interaction/         # чистая доменно-нейтральная модель взаимодействий (без pygame)
  model.py           # Target / ActionSpec / OutcomeSpec / прогнозы / розыгрыш
  demo.py            # абстрактные демо-объекты, действия и исходы
```

* **`Scene`** — один экран: `on_enter/on_exit`, `layout(w, h)`, `handle_event`,
  `update(dt)`, `draw(surface)`.
* **`SceneManager`** — стек сцен: `go` (сменить корневой экран), `push`/`pop`
  (оверлеи). Экземпляры в стеке сохраняются, поэтому пауза не сбрасывает партию:
  при `pop` восстанавливается тот же объект `GameScene`.
* **`App`** владеет окном PyGame и шрифтами и переиспользует из `game_engine.py`
  `FontSet`, `compute_window_size`, `_probe_font` и логгер (`GAME_LOG`).
* Слои `overlay` рисуются поверх нижележащей сцены (полупрозрачное затемнение) —
  так устроена пауза.

## Система сохранений и автосохранений

Каталог `saves/` (в корне репозитория; добавлен в `.gitignore`):

| Файл | Назначение |
|------|-----------|
| `settings.json` | Пользовательские настройки (язык, автосохранение, громкости, скорость текста, полный экран) |
| `autosave.json` | Автосохранение (пишется при старте и завершении партии, а также при выходе в меню) |
| `slot_1..3.json` | Ручные слоты (кнопка «Сохранить» из паузы) |

Запись — атомарная (временный файл + `os.replace`), UTF-8. Битый JSON не роняет
приложение: чтение возвращает `None` и пишет предупреждение в лог.

Формат слота — метаданные партии:

```json
{ "version": 1, "name": "match", "created": "...", "updated": "...",
  "seed": 3, "tick": 128, "winner": null, "finished": false,
  "steps": 2000, "with_env": true,
  "profile_rl": "CANON", "profile_ai": "CANON" }
```

**Возобновление партии.** Полное состояние партии не сериализуется: движок
(`MatchEngine`) детерминирован по `seed`, поэтому «Продолжить»/«Загрузить»
пересоздают партию с сохранённым seed и **доигрывают до сохранённого такта**
(`game_engine.GameApp.start_match(seed, resume_tick)`) — состояние
реконструируется повторным проигрыванием. Ограничение осознанное: сериализация
внутреннего состояния агентов/среды избыточна, пока партия воспроизводима.

## Встраивание игрового поля (изменения `game_engine.py`)

`GameApp` получил **обратно совместимые** параметры, превращающие его в сцену:

* `GameApp(fonts, screen=None, on_escape=None, seed, steps, with_env,
  profile_rl, profile_ai)`: при переданном `screen` окно не создаётся — рисуем в
  чужой surface;
* `draw(surface=None)` — при `surface is None` поведение прежнее (рисуем в своё
  окно и делаем `flip`); с чужим surface `flip` делает вызывающий;
* `handle_events(events=None)` — при `None` берём события из очереди pygame
  (автономный режим), иначе обрабатываем переданный список (сценный слой);
* `on_escape` — `ESC` вызывает колбэк (открыть паузу) вместо выхода;
* `on_resize(w, h)`, `start_match(seed, resume_tick)`, `progress()`,
  `new_match(seed=None)` — вспомогательное API для сценного слоя.

Проверено, что одиночный режим (`python3 game_engine.py`) работает как раньше.

## Пошаговое стратегическое поле (RTS + ролевой отыгрыш)

`ui/scenes/battlefield.py` — отдельная сцена, не заменяющая арену. Стратегическая
специфика:

* изометрическая сетка 11×9; клетки рисуются ромбами, юниты — плейсхолдерами
  `[ UNIT ]`; выбор юнита кликом, движение — правым кликом (радиус 2 клетки);
* контакт = соседняя клетка; только в контакте доступен единый приказ
  `ATTACK` (плюс покой, лечение и удержание). Легаси-стихии
  `FIRE`/`WATER`/`EARTH` убраны из игрового UI: они не отражали войсковой
  слой и дублировали внутренние имена `simulation.py`, которые остались
  только в каноне;
* очки команд (CP) — тактический ресурс UI: движение/атака тратят, ход и
  занятая высота восполняют; высота даёт мораль, но не меняет физику модели;
* здоровье командира — отдельная шкала `H`: HUD арены показывает `H=...`,
  панель поля боя — бар «здоровье». `--health-factors` или
  `BattlefieldModel(health_factors=...)` задают `aging/illness/stress/care`;
  смерть при `H<=0` завершает бой, а `F=0` — ещё нет. Болезнь —
  `sickness ∈ [0,1]`: HUD арены показывает `sick ...`, начальное значение
  задаётся `--sickness` или `BattlefieldModel(sickness=...)`. Лечение —
  кнопка «ЛЕЧЕНИЕ»/клавиша `T` в тактическом поле и шестое действие в
  арене; она включается только при `sickness > 0`. Панель поля боя болезнь
  пока не показывает: это состояние доступно в снапшоте модели;
* время арены идёт через `core41.SimulationClock`: один такт = 1 с при `1x`,
  скорости `pause/1x/2x/4x/8x/16x`, авто-пауза и догон не более 64 тактов
  за кадр. При потере фокуса отрисовка пропускается, `update` продолжается;
  поле боя пока пошаговое;
* бой считается `core41.run_duel_tick` с `ArenaAgent`/`BDIPolicy` на стороне
  противника, захват — `core41.check_capture`; канон `simulation.py` и его пин
  не затрагиваются. `UtilityAI` больше не создаётся в арене и остаётся
  baseline/экспериментом.

Ролевой слой: профиль командира (`CANON`/`ORTHODOX`/`ZEALOT`), мораль, черты и
репутация — переменные UI, а не метрики модели. Диалоги двуязычны, хранятся в
`ui/battlefield.py` (`DIALOGUES`) и меняют CP/мораль/профиль/черты. Экран
показывает журнал, портрет-плейсхолдер, панель приказов и панель диалога.

Запуск: `python3 main.py`, затем «Поле боя (RTS)»; либо
`python3 -m ui --scene battlefield`. Логика сцены тестируется без pygame —
`tests/test_battlefield.py`.

## Экран взаимодействий (доменно-нейтральный каркас)

`ui/scenes/interaction.py` — экран из трёх панелей:

* **с кем можно взаимодействовать** — доступные объекты;
* **что с ними можно сделать** — действия выбранного объекта; панель
  раскрывается только после выбора объекта;
* **что может произойти** — шумный прогноз исходов; после выполнения здесь же
  показывается фактический результат.

Модель живёт в отдельном чистом пакете `interaction/` (без pygame и без
зависимости от канона). Она поддерживает диапазоны вероятностей, уверенность,
скрытые исходы и долю вообще неизвестных эффектов (`unknown_share`). Прогнозы
стабильны и кешируются, а розыгрыш детерминирован по `seed`; поэтому экран
можно тестировать и воспроизводить. Демо-контент абстрактный — его место
займёт контент будущей игры.

Запуск: «Взаимодействие» в главном меню, `python3 main.py --interaction` или
`python3 -m ui --scene interaction`. Подробности API и расширения —
[`INTERACTION.md`](INTERACTION.md); чистые тесты — `tests/test_interaction.py`.

## Плейсхолдеры и дальнейшие шаги

* Вместо ассетов используется `theme.draw_placeholder` — рамка с диагоналями и
  подписью `[ IMG: <ключ> ]`. Ключи: `menu_hero`, `intro_arena`,
  `intro_transfer`, `intro_conjuncture`, `about_logo`, `portrait_player`,
  `portrait_enemy`, `unit`.
* Следующие шаги (вне этого слоя): реальные 2-D ассеты (фон, иконки, кнопки,
  портреты, тайлы), звук/музыка (ползунки громкости уже сохраняются),
  клавиатурная навигация по меню, локальные профили игрока, сохранение
  стратегической партии (сейчас `snapshot()` готовит данные, но слоты пишут
  только классическую арену). Персонажи и локации — 3-D слой в рамках другого
  проекта.

## Тесты

`tests/test_ui.py`:

* без графики (работают в CI без pygame) — настройки, слоты, битый JSON,
  двуязычный контент, «`ui.save` свободен от pygame», чистая логика
  стратегического поля (`tests/test_battlefield.py`);
* с графикой (`pytest.importorskip("pygame")`, `SDL_VIDEODRIVER=dummy`) —
  старт в меню, отрисовка всех экранов (включая `battlefield` и
  `interaction`), раскрытие действий/исходов, нарратив → партия и автосейв,
  пауза сохраняет партию, сохранение/загрузка слота, клик по кнопке.
* чистый фреймворк взаимодействий — `tests/test_interaction.py` (без pygame:
  выбор, шум/диапазоны, скрытые и неизвестные исходы, детерминизм, история).

Ручной headless-прогон (без assert-обвязки) полезен при отладке:

```bash
SDL_VIDEODRIVER=dummy python3 -m ui --scene menu
```
