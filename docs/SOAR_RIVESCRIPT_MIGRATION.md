## 0. Решение в одном абзаце

**Soar** становится единственным когнитивным ядром: рабочая память,
продукции, выбор операторов, импasses, чанкинг, семантическая и
эпизодическая память, обучение предпочтений. **RiveScript** становится
языковой поверхностью: детерминированное сопоставление фраз, слоты,
топики, перефразы и шаблоны ответов. **Python** остаётся средой: он
строит перцепты, исполняет команды, считает формулы мира, проверяет
инварианты, сохраняет и загружает состояние. Данные в JSON остаются
источником истины; `.soar` и `.rive` генерируются из них, а не пишутся
второй раз вручную.

Миграция идёт по стратегии «удушения» (strangler): новый слой включается
флагом, работает в теневом режиме рядом со старым, сравнивается на
золотом корпусе и только потом становится основным. Старый слой удаляется
после прохождения критериев, а не в один коммит.

## 1. Что входит и что не входит

### 1.1. Входит

| Подсистема | Текущее место | Что должно перейти |
|---|---|---|
| Разбор фразы | `campaign/dialogue/morphology.py`, `parser.py`, `morph.py` | поверхностный NLU в RiveScript, морфология как object macro |
| Семантика и вывод | `campaign/dialogue/semantics.py`, `inference.py`, `knowledge.py` | интерпретация и вывод в Soar |
| Прагматика и план ответа | `planner.py`, `answers*.py`, `social.py`, `style.py` | выбор речевого акта и содержания в Soar |
| Синтез | `realize.py`, `configs/dialogue/synthesis.json` | шаблоны RiveScript + композиционный realizer |
| Состояние диалога | `state.py` | рабочая память Soar + снимок Python |
| BDI | `bdi.py`, `actor.py`, `character.py` | структуры Soar, формулы остаются в Python |
| Выбор работы NPC | `npc_policy.py`, `automata_ai.py` | продукции Soar с числовыми предпочтениями |
| Решения фракций | `automata_ai.py`, `dispatch_*.py`, `state_machine.py` | выбор действия/приказа в Soar; исполнение автомата — Python |
| Дневная рутина | `routine.py`, `world_day.py` | изменение потребностей — Python, решение — Soar |
| Обучение | `agents/policies.py`, `core41/env.py` | RL Soar для выбора операторов; арена остаётся полигоном |

### 1.2. Не входит

- Формулы мира, экономика, бой, сеть органов, эффекты и условия
  (`effects.py`, `conditions.py`, `faction_state.py`) — это среда, а не
  когниция. Soar не пересчитывает их «своими» правилами.
- Рендеринг, ввод-вывод, PyGame, сохранения как файловый формат.
- Сюжет: хроника по-прежнему вычисляется из состояния и журнала
  (`campaign/chronicle.py`), см. [`NARRATIVE_INVARIANT.md`](NARRATIVE_INVARIANT.md).
- LLM, эмбеддинги, облачные API. Ограничение «без чёрного ящика»
  сохраняется: Soar и RiveScript детерминированы и трассируемы.

## 2. Почему именно Soar и RiveScript

### 2.1. Разделение ответственности

| Вопрос | Soar | RiveScript | Python |
|---|---|---|---|
| Что сказал игрок? | интерпретация кандидатов | сопоставление фраз и слотов | нормализация, морфология |
| Что это значит в мире? | операторы интерпретации | — | проверка онтологии |
| Что ответить? | речевой акт и содержание | поверхностная форма | композиция сложных ответов |
| Что сделать? | выбор действия/приказа | — | валидация и исполнение |
| Чему научиться? | чанкинг, RL предпочтения | — | чекпойнты, метрики |
| Как сохранить? | снимок WM | — | сериализация и версии |

**Правило границы:** RiveScript не принимает решений о мире, Soar не
рендерит текст и не пишет состояние напрямую. Любая команда Soar проходит
через Python-валидатор и существующие единственные точки записи
(`apply_effects`, `ActionBridge`, `start_action`, `issue_order`).

### 2.2. Что даёт Soar

- Продукции и рабочая память вместо разрозненных эвристик.
- Единый цикл «предложить → выбрать → применить» для диалога, BDI и
  фракций.
- Импассы и подсостояния: неоднозначность фразы, конфликт целей,
  отсутствие данных — это штатные ситуации, а не `if/else`.
- Чанкинг: повторяющиеся выводы становятся правилами.
- SMEM/EPMEM: факты мира и эпизоды разговора без отдельного самописного
  хранилища.
- RL: предпочтения операторов вместо внешней политики, если это
  выдержит сравнение с `NeedPolicy`.

### 2.3. Что даёт RiveScript

- Детерминированные триггеры, wildcard-слоты, синонимы, топики,
  `%`-продолжения, `@`-перефразы, `*`/`#`/`_`-подстановки.
- Object macros на Python: морфология, числа, качественные уровни,
  поиск сущностей, сборка семантического кадра.
- Прозрачная отладка: сработавшее правило видно по id.
- Дешёвый fallback и шаблоны уточнений.

### 2.4. Чего они не делают

- RiveScript не является морфологическим анализатором и не решает
  падежную неоднозначность русского языка. Это делают словарь
  (`configs/dialogue/lexicon.json`), `pymorphy3`/`morph.py` и Soar.
- Soar не заменяет chart parser «из коробки». Глубокий разбор длинных
  фраз остаётся отдельной задачей; в переходный период допустим fallback
  на текущий `ChartParser`.
- Ни один из них не отменяет Data-Driven: контент остаётся в JSON.

## 4. Целевая архитектура

### 4.1. Диалоговый цикл

```
текст игрока
   │
   ▼
[0] Нормализация и токенизация            Python, детерминированно
   │
   ▼
[1] Морфология и словарные признаки       Python / RiveScript object macro
   │
   ▼
[2] Сущности, числа, время, местоимения   Python + онтология мира
   │
   ▼
[3] RiveScript: триггеры, слоты, топик    configs/rive/ru/*.rive
   │        intent + slots + confidence + rule_id
   ▼
[4] Сборка типизированного кадра          Python, схема UtteranceFrame
   │
   ▼
[5] Soar input-link                       мост, JSON-протокол
   │        интерпретация → речевой акт → содержание → команда
   ▼
[6] Soar output-link                      say / clarify / act / remember
   │
   ▼
[7] Валидация и исполнение                Python: ActionBridge, effects
   │
   ▼
[8] NLG                                   RiveScript-шаблоны + Realizer
   │
   ▼
ответ + трассировка
```

### 4.2. Цикл агента мира (NPC, фракция)

```
тик мира (Python)
   │  перцепты: потребности, убеждения, угрозы, органы, отчёты, время
   ▼
Soar input-link
   │  предложить операторы → выбрать → применить
   ▼
Soar output-link
   │  start_action / issue_order / move / speak / wait
   ▼
Python: validate → существующая точка записи → событие в журнал
   │
   ▼
следующий тик
```

Симуляция не ждёт Soar бесконечно: у моста есть бюджет тика и
детерминированный таймаут. При таймауте срабатывает явно
задокументированная политика отката (последний допустимый оператор или
эвристика), а факт фиксируется в журнале.

### 4.3. Размещение Soar-агентов

| Тип агента | Рекомендация | Причина |
|---|---|---|
| Именной NPC | отдельный Soar-агент | свои BDI, память, чанкинг |
| Лидер фракции | отдельный Soar-агент | стратегические операторы и приказы |
| Массовый NPC | общий «толповый» агент с несколькими `agent-id` | цена решения на каждого |
| Диалог игрока с NPC | тот же агент NPC | единая память и BDI |
| Арена/обучение | внешние политики `agents/` | полигон, не игровой NPC |

Решение «отдельный агент на NPC» проверяется в Phase 2 по бюджету
времени; до этого архитектура допускает оба варианта за фасадом
`campaign/cognition/`.

### 4.4. Структура рабочей памяти Soar

```
S1
  ^agent <id>
     ^self ^needs ^beliefs ^intentions ^traits ^morale ^force ^energy
     ^dialogue ^memory ^world ^faction ^time
  ^input-link
     ^tick ^percept ^utterance ^frame ^entities ^events
  ^output-link
     ^command ^say ^act ^order ^remember
```

Правила именуются по схеме `<домен>-<оператор>-<роль>`, например
`nlu-interpret-select-frame`, `npc-propose-work-eat`,
`faction-select-order-reinforce`. Имена и id попадают в трассировку.

### 4.5. RiveScript-слой

```
configs/rive/
  ru/
    _common.rive        # синонимы, служебные объекты, fallback
    greeting.rive
    ask_world.rive
    ask_bdi.rive
    act.rive
    clarify.rive
    meta.rive
  objects.py            # object macros: morph, number, quality, entity
```

Триггеры генерируются из:

- `configs/dialogue/lexicon.json` — леммы, формы, синонимы;
- `configs/dialogue/grammar.json` — продуктивные конструкции;
- `configs/dialogue/actions.json` — глаголы действий и псевдонимы;
- `configs/dialogue/paraphrases.json` — перефразы;
- `configs/dialogue/fallback.json` — уточнения и отказы;
- `configs/dialogue/ontology.json` — типы сущностей.

Ручные `.rive` допустимы только для служебных фраз (приветствие,
«не понял», «уточни»). Всё предметное — генерируется и проверяется
линтером, иначе появляется второй источник истины.

### 4.6. Мост Python ↔ Soar

Протокол версионируется (`soar_bridge.v1`) и не зависит от способа
запуска Soar.

```json
{
  "agent_id": "npc:irina",
  "tick": 142,
  "snapshot_version": 3,
  "input": {
    "utterance": {"text": "...", "frame": {}},
    "world": {"location": "...", "time": "..."},
    "self": {"needs": {}, "beliefs": [], "intentions": []}
  }
}
```

```json
{
  "commands": [
    {"kind": "say", "act": "answer", "content": {}},
    {"kind": "act", "action_id": "inspect", "target": "..."}
  ],
  "trace": {"operators": [], "impasse": null},
  "timing_ms": 3.2
}
```

Правила моста:

1. Soar не пишет в состояние игры. Только команды.
2. Каждая команда имеет `kind`, `id`, `origin` и проходит валидацию.
3. Неизвестная команда — ошибка моста, а не молчаливый no-op.
4. Ответ детерминирован при одном входе и одной версии агента.
5. Снимок Soar сериализуется вместе с сохранением игры; версия
   несовместима — явная миграция или отказ, не «тихое» обнуление.

## 5. Конвейер NLU (основной акцент)

### 5.1. Стадии и контракты

| # | Стадия | Вход | Выход | Где | Отказ |
|---|---|---|---|---|---|
| 0 | Нормализация | сырой текст | NFC, нижний регистр, ё→е, токены | Python | пустой ввод → `empty` |
| 1 | Морфология | токены | лемма, POS, падеж, число, род, время | словарь + `morph.py` + pymorphy3 | неизвестное слово → гипотеза по суффиксам |
| 2 | Сущности | токены + мир | id сущностей, числа, даты, местоимения | Python + `ontology.json` | нет кандидата → `unknown_entity` |
| 3 | Триггеры | нормализованная фраза + топик | `intent`, `slots`, `rule_id`, `confidence` | RiveScript | нет триггера → `fallback` |
| 4 | Кадр | кандидат + токены + сущности | `UtteranceFrame` | Python | неполный кадр → `clarify` |
| 5 | Референция | кадр + состояние диалога | подставленные референты, эллипсис | Python + Soar | неоднозначно → `clarify` |
| 6 | Интерпретация | кадр на input-link | выбранный смысл, уверенность | Soar | конфликт → импasse → уточнение |
| 7 | Прагматика | смысл + BDI + политика | речевой акт, содержание | Soar | запрет раскрытия → отказ/уход |
| 8 | Команда | решение | `say`/`act`/`clarify` | Soar → Python | невалидно → fallback + лог |

### 5.2. Контракт вызова и оценка уверенности

```python
def understand(text, *, state, world, topic="default"):
    """Вернуть Frame | Clarification | Reject. Действий не выполняет."""
```

`understand` — чистая функция над снимком: она не пишет в состояние, не
вызывает `ActionBridge` и не меняет BDI. Это позволяет гонять её в
теневом режиме и кешировать по `(text, snapshot_version, topic)`.

Уверенность считается детерминированно, без обучения:

```
confidence =
    0.45 * specificity(rule)      # насколько правило специфично
  + 0.30 * slot_fill(frame)       # доля обязательных слотов
  + 0.25 * lex_coverage(tokens)   # доля слов, известных лексикону
  - 0.20 * unknown_penalty        # неизвестные слова/сущности
```

Порог `accept` и `clarify` — данные в `configs/rive/ru/_common.rive`
(или в JSON-манифесте), а не константы в Python. Если несколько кадров
проходят порог `accept`, выбирает Soar; если ни один — `clarify` с
вариантами, а не общий fallback.

### 5.3. Схема `UtteranceFrame`

```json
{
  "id": "u-142-3",
  "text": "почему империя считает республику незаконной после эдикта",
  "tokens": [
    {"surface": "империя", "lemma": "империя", "pos": "N", "case": "nom"},
    {"surface": "республику", "lemma": "республика", "pos": "N", "case": "acc"}
  ],
  "intent": "ask_reason",
  "speech_act": "question",
  "predicate": "consider_illegitimate",
  "args": {
    "agent": "faction.empire",
    "patient": "faction.republic",
    "theme": "legitimacy"
  },
  "slots": {
    "time": "after_edict",
    "polarity": "positive"
  },
  "referents": [],
  "confidence": 0.86,
  "evidence": ["rive:ask_reason_why", "lex:consider", "entity:faction.empire"],
  "unknowns": []
}
```

Требования к кадру:

- все id проходят через онтологию и снимок мира;
- `confidence` — детерминированная функция специфичности правила,
  полноты слотов и покрытия лексики, а не «вероятность от модели»;
- `evidence` хранит id сработавших триггеров и словарных статей;
- `unknowns` явно перечисляет, что не распознано.

### 5.4. Генерация RiveScript-триггеров

Пример сгенерированного правила (иллюстрация, не финальный синтаксис):

```rive
+ почему (империя|империи) (считает|думает) (республику|республика) (незаконной|незаконная)
@ ask_reason_legitimacy

+ [а] почему *
@ ask_reason_generic
```

Правила генерации:

1. Одна лемма — один набор словоформ из лексикона; синонимы — через
   `(форма1|форма2)`.
2. Свободный порядок слов не эмулируется перебором всех перестановок.
   Вместо этого — несколько продуктивных шаблонов и `*`-слоты, а
   падежная проверка остаётся в кадре.
3. Слоты именуются (`<agent>`, `<patient>`, `<theme>`), а не `*` без
   имени, чтобы кадр был типизирован.
4. Для каждого интента обязателен `@`-redirect на канонический обработчик;
   дублирующие триггеры проверяются линтером.
5. Топики переключаются по фазе разговора, а не по глобальному состоянию.
6. Fallback `*` не должен перехватывать фразы, для которых есть
   специализированный триггер; порядок и приоритет фиксируются.

### 5.5. Морфология и русский язык

- Словарные формы — основной путь; `pymorphy3` — только для неизвестных
  слов и синтеза, как сейчас.
- Object macro `morph` возвращает лемму и признаки; macro `agree`
  проверяет согласование; macro `case` выбирает падеж для слота.
- Свободный порядок слов обрабатывается не «всеми перестановками», а
  набором конструкций + проверкой падежей в кадре.
- Отрицание, модальность, время и вид выносятся в отдельные поля кадра,
  а не растворяются в тексте.
- Для многозначных предлогов и союзов сохраняется несколько кандидатов;
  выбор — за Soar, а не за regex.

### 5.6. Неоднозначность, уточнение и отказ

| Ситуация | Поведение |
|---|---|
| Один кадр с высокой уверенностью | сразу в Soar |
| Несколько кадров | Soar предлагает интерпретации, выбирает по контексту |
| Ничья / нет контекста | `clarify` с конкретным вопросом |
| Неизвестное слово | гипотеза морфологии; если критично — `clarify` |
| Неизвестная сущность | список ближайших сущностей из мира |
| Интент вне мира | честный отказ, без выдумывания |
| Запрет раскрытия (D6.3) | отказ/уход, трассировка причины |

Уточнение — не «не понял» без продолжения, а вопрос с вариантами:
«Вы про законность Империи или Республики?».

### 5.7. Двойной прогон и метрики NLU

В переходный период каждый вход проходит и старый, и новый конвейер:

```
text → legacy(parse, intent, plan)  ─┐
     → rivescript(frame)            ─┼→ сравнение → отчёт
     → soar(shadow decision)        ─┘
```

Метрики:

- `intent_accuracy` — совпадение с золотым корпусом;
- `slot_f1` — полнота и точность слотов;
- `frame_exact` — доля полностью совпавших кадров;
- `fallback_rate` — доля `fallback` на поддерживаемом множестве;
- `clarification_rate` — доля уточнений;
- `unknown_word_rate` — доля неизвестных лексем;
- `determinism_hash` — побитовый хеш ответа при повторном прогоне;
- `latency_p50/p95` — на ход и на тик NPC.

Порог переключения фазы задаётся до начала работ, а не после просмотра
результата. Предлагаемый стартовый порог: `intent_accuracy` не ниже
легаси на золотом корпусе, `slot_f1 ≥ 0.90`, `frame_exact ≥ 0.80`,
`fallback_rate ≤ 5%` на поддерживаемом множестве, `latency_p95` в
бюджете.

Золотой корпус делится на категории, чтобы метрика не «съедала» слабые
места:

| Категория | Пример | Что проверяет |
|---|---|---|
| Вопрос о мире | «Почему Империя считает Республику незаконной?» | сущности, причина, вывод |
| Вопрос о BDI | «Чего боится твой лидер?» | доступ к потребностям и убеждениям |
| Действие | «Утешь его» | глагол, адресат, форма работы |
| Продолжение | «А почему?» | QUD, эллипсис, референты |
| Уточнение | «О ком ты?» | восстановление после неоднозначности |
| Отказ/табу | «Скажи мне секрет» | политика раскрытия |
| Неизвестное | «Где ближайший космопорт?» | честный fallback |
| Шум | пустой ввод, пунктуация, опечатки | устойчивость |

Минимум для Phase 1: 40 фраз на категорию, по 10 seed-снимков; корпус
версионируется вместе с фикстурой и не переписывается под результат
без отдельного ревью.

### 5.8. Линтер NLU

Новый линтер (`campaign/cognition/lint_nlu.py`) проверяет:

- у каждого действия/интента есть хотя бы один триггер;
- у каждого триггера есть канонический обработчик и схема слотов;
- слоты ссылаются на типы онтологии;
- нет недостижимых топиков и «висячих» `@`-перефразов;
- сгенерированные `.rive` совпадают с JSON-источником;
- нет ручных предметных триггеров вне разрешённого списка;
- fallback не перекрывает специализированные правила.

Линтер входит в CI рядом с `campaign.dialogue.lint` и
`campaign.content_lint`.

## 6. Перенос BDI и решений

### 6.1. Что остаётся в Python

- Рост потребностей, spillover, пороги, урон силе/энергии, смерть —
  формулы `bdi.py` и `configs/characters/bdi.json`.
- Суточная рутина и удовлетворение — `routine.py`, `world_day.py`.
- Эффекты работ, условия, активы, органы — `effects.py`,
  `conditions.py`, `faction_state.py`.
- Валидация действий и единственные точки записи.

### 6.2. Что переходит в Soar

- Какое намерение активно и как оно конкурирует с другими.
- Какую работу взять при нескольких доступных.
- Когда отдать приказ, кому и какой.
- Как реагировать на доклад/угрозу.
- Какой речевой акт выбрать и что раскрыть.
- Когда уточнить, отказать или промолчать.

### 6.3. Маппинг BDI → рабочая память

| BDI | Soar WM | Примечание |
|---|---|---|
| `needs[name]` | `^self ^needs ^<name> ^value` | формула роста — Python |
| `traits` | `^self ^traits ^<name>` | стабильные признаки |
| `beliefs` | `^self ^beliefs ^<id> ^subject ^predicate ^object ^value` | SMEM-кандидат |
| `intentions` | `^self ^intentions ^<id> ^target ^essence` | выбор — Soar |
| `conditions` | `^self ^conditions ^<name>` | здоровье/рана |
| `morale/force/energy` | `^self ^morale`, `^force`, `^energy` | числа |
| история | EPMEM | эпизоды диалога и решений |

### 6.4. `NeedPolicy` → продукции

Текущая политика выбирает `(option_id, need, base)` по весу
`1 + weight(need) * value`. В Soar это:

- операторы-кандидаты с `^work ^id`, `^need`, `^base`;
- числовое предпочтение `^operator <o> = <score>` или
  `^operator <o> *`;
- веса из `ai_model.npc_policy` компилируются в константы/атрибуты;
- при равных оценках — детерминированный tie-break по id.

Критерий: на золотых seed выбор совпадает с `NeedPolicy` не менее чем в
95% случаев, а расхождения объяснены (например, Soar учёл
дополнительный контекст). Если совпадения нет — политика остаётся
основной, Soar получает более узкую роль.

### 6.5. Фракции и автоматы

`state_machine.py` остаётся исполнителем состояний: это динамика мира,
а не решение агента. Soar выбирает:

- действие из доступных;
- приказ и получателя;
- реакцию на доклад;
- приоритет между потребностью, доктриной и угрозой.

Автомат по-прежнему применяет `on_enter`/`on_tick` через `effects.py`.
Soar не дублирует переходы и не пишет активы напрямую.

### 6.6. Обучение

- Soar RL — предпочтения операторов для игровых NPC.
- `agents/` (BDI/QTable/MLP/Utility) остаётся для арены, `CampaignEnv` и
  офлайн-бенчмарков; это не когниция каждого NPC.
- Нельзя одновременно учить внешнюю политику и Soar RL на одном решении:
  выбирается один владелец, второй — только для сравнения.
- Чекпойнты версионируются; снимок Soar и чекпойнт RL сохраняются
  раздельно.

## 7. Фазы миграции

Оценки — для одного-двух разработчиков; треки NLU и решений после Phase 0
можно вести параллельно.

### Phase 0. Фундамент и spike (1–2 недели)

**Цель:** доказать, что Soar и RiveScript вообще запускаются в целевом
окружении, и зафиксировать базовую линию.

Deliverables:

- spike: Soar-агент с input/output-link и одной продукцией;
- spike: RiveScript с русскими триггерами и object macro;
- решение по биндингу: официальные SML Python bindings или subprocess +
  JSON/Tcl-протокол;
- `campaign/cognition/` — фасад с `nlu()` и `decide()`, пока delegating
  в легаси;
- запись золотого корпуса: `(seed, snapshot, input) → trace`;
- флаги `ai_backend=legacy|shadow|soar`, `nlu_backend=legacy|shadow|rive`;
- CI-джоб для опциональных зависимостей (не блокирует основной, пока
  Phase 1 не принята).

**Exit:** Soar и RiveScript работают в CI; 100 эталонных фраз проходят
RiveScript; поведение игры не изменилось; корпус воспроизводим.

**Rollback:** флаги выключены, легаси не тронут.

### Phase 1. RiveScript shadow NLU (2–3 недели)

**Цель:** новый NLU работает рядом, но не отвечает игроку.

Deliverables:

- компилятор JSON → `.rive` + манифест;
- object macros `morph`, `number`, `quality`, `entity`;
- сборка `UtteranceFrame`;
- двойной прогон и отчёт метрик;
- линтер NLU;
- fallback на `ChartParser` при низкой уверенности.

**Exit:** на золотом корпусе `intent_accuracy` не ниже легаси,
`slot_f1 ≥ 0.90`, `frame_exact ≥ 0.80`; `fallback_rate ≤ 5%` на
поддерживаемом множестве; ответы игры побитово те же.

**Rollback:** `nlu_backend=legacy`; сгенерированные файлы не влияют на
игру.

### Phase 2. Soar shadow для выбора работы NPC (3–4 недели)

**Цель:** Soar принимает решения в тени `NeedPolicy`.

Deliverables:

- компилятор BDI/весов → Soar WM и продукции;
- операторы работ, предпочтения, tie-break;
- сравнение выбора на одинаковых seed;
- включение по фракции/типу NPC через флаг;
- метрики: удовлетворённость потребностей, разнообразие работ,
  выживаемость, доля невалидных действий.

**Exit:** согласие с `NeedPolicy` ≥ 95% или объяснённые расхождения;
детерминизм; бюджет тика; нет невалидных действий; откат работает.

**Rollback:** `ai_backend=legacy` для конкретной фракции.

### Phase 3. Soar shadow для прагматики диалога (4–6 недель)

**Цель:** вывод, раскрытие и план ответа — в Soar, синтез пока старый.

Deliverables:

- операторы интерпретации кадра;
- операторы выбора речевого акта и содержания;
- политика раскрытия D6.3 как продукции/ограничения;
- трассировка доказательства в Soar;
- сравнение ответов с легаси на корпусе.

**Exit:** эквивалентность ответов на корпусе (с учётом допустимых
формулировок), сохранённая трассировка, read-only инвариант, нет
регрессий по безопасности раскрытия.

**Rollback:** `dialogue_backend=legacy`.

### Phase 4. RiveScript как основной NLU + Soar-интерпретация (4–6 недель)

**Цель:** поддерживаемые интенты идут через RiveScript и Soar.

Deliverables:

- RiveScript включён по умолчанию для поддерживаемого множества;
- `ChartParser` — только fallback для длинных/сложных фраз;
- уточнения и восстановление после ошибок;
- сохранение/загрузка состояния диалога и Soar WM;
- отчёты покрытия и неизвестной лексики.

**Exit:** `fallback_rate ≤ 10%` в живой игре; уточнения корректны;
сейвы совместимы; latency в бюджете; старый NLU можно выключить без
потери поддерживаемых сценариев.

**Rollback:** переключение на `nlu_backend=legacy` и старый state.

### Phase 5. Soar для BDI, фракций и мира (4–6 недель)

**Цель:** все игровые решения агентов — в Soar; Python — среда.

Deliverables:

- BDI-намерения и конкуренция целей в Soar;
- выбор действий/приказов фракций;
- реакции на доклады и угрозы;
- RL-предпочтения (если проходят сравнение);
- LOD для массовых NPC;
- полные прогоны кампании и мира.

**Exit:** кампания и мир проходят без регрессий; метрики не хуже
легаси; производительность в бюджете; сейвы и детерминизм; откат по
фракции/миру.

**Rollback:** `ai_backend=legacy`; старые `NeedPolicy` и эвристики
сохраняются до Phase 6.

### Phase 6. Демонтаж GOFAI (2–3 недели)

**Цель:** один когнитивный путь, без двойного maintenance.

Deliverables:

- удаление `ChartParser`/`InferenceEngine`/`NeedPolicy`-эвристик, если
  они больше не нужны;
- удаление флагов shadow;
- обновление `SOURCE_OF_TRUTH`, `CONTENT.md`, `ONBOARDING`, `TODO`;
- fitness-тесты: никто вне `campaign/cognition` не импортирует Soar;
- финальный отчёт метрик и известных ограничений.

**Exit:** полный `pytest` зелёный; линтеры чистые; документация
соответствует коду; старые модули удалены или помечены архивом.

## 9. Тестирование и приёмка

### 9.1. Уровни

| Уровень | Что проверяет |
|---|---|
| Unit | триггеры, object macros, продукции, мост, команды |
| Contract | `UtteranceFrame`, `soar_bridge.v1`, снимки |
| Golden | ответы и решения на записанном корпусе |
| Parity | новый слой против легаси на одинаковых seed |
| Property | случайные кадры/команды не ломают инварианты |
| Soak | длинная кампания/мир без утечек и деградации |
| Save/load | снимок Soar + состояние игры + версии |
| Performance | p50/p95 на ход и на тик |

### 9.2. Инварианты

- Один вход + один снимок + одна версия → один выход.
- Soar не пишет состояние напрямую.
- RiveScript не выбирает действия мира.
- Любое действие проходит через существующую точку записи.
- Сюжет не задаётся в Soar/RiveScript: хроника остаётся проекцией.
- 16 потребностей не меняются в составе.
- `content_lint` и `dialogue.lint` остаются зелёными.

### 9.3. Бюджеты (стартовые, уточняются в Phase 0)

- NLU на ход: p95 ≤ 20 мс.
- Решение NPC на тик: p95 ≤ 5 мс при LOD-пуле.
- Полный ход диалога: p95 ≤ 100 мс без учёта рендера.
- Память Soar на агента: ≤ 32 МБ (проверить на 100 NPC).
- Кампания на 200 ходов: без роста времени тика более чем в 2 раза.

## 10. Риски и смягчение

| Риск | Влияние | Смягчение |
|---|---|---|
| Нет стабильных Python-биндингов Soar | блокирует старт | spike в Phase 0; subprocess + JSON как fallback |
| Производительность Soar на каждого NPC | высокое | LOD, общий агент, бюджеты, профилирование |
| Недетерминизм (таймеры, RNG, порядок) | ломает воспроизводимость | фиксированный цикл, seed, запрет wall-clock, хеш-тесты |
| Сложность отладки Soar | высокое | трассировка операторов, текстовые отчёты, малые агенты |
| RiveScript не тянет русскую морфологию | среднее | object macros, fallback на chart parser, падежный кадр |
| Двойной источник истины JSON vs `.soar/.rive` | высокое | генерация + линтер + CI-дифф |
| Конфликт с Data-Driven каноном | высокое | JSON — источник; Soar-правила — генерируемый слой; ручные только служебные |
| Долгая двойная поддержка | высокое | строгие exit-критерии и даты отключения |
| Сейвы несовместимы | высокое | версия снимка, миграции, отказ вместо тихого сброса |
| Обучение Soar RL расходится с `NeedPolicy` | среднее | сравнение, откат, один владелец решения |
| Лицензии зависимостей | среднее | проверить в Phase 0, зафиксировать в документах |
| Навыки команды | высокое | парные сессии, примеры, малые вертикальные срезы |

## 12. Открытые решения (нужны до Phase 1)

1. **Биндинг Soar:** официальные SML Python bindings или subprocess?
   Критерии: Python 3.12, Linux CI, снимки, скорость, лицензия.
2. **Гранулярность агентов:** отдельный Soar на именного NPC или общий
   пул? Нужен замер Phase 2.
3. **Судьба chart parser:** оставить как deep fallback навсегда или
   удалить после Phase 4? Предложение: удалить, если покрытие
   поддерживаемого языка достигнуто.
4. **Граница RiveScript/Soar:** где заканчивается сопоставление и
   начинается интерпретация? Предложение: RiveScript отдаёт кадр, Soar
   выбирает смысл.
5. **Владелец обучения:** Soar RL или внешние политики? Предложение:
   Soar RL для игровых NPC, `agents/` — для арены и бенчмарков.
6. **Формат снимка Soar:** родной Soar + JSON-обёртка или полностью
   JSON? Влияет на сейвы и миграции.
7. **Локализация:** только русский или сразу несколько языков? Влияет
   на генерацию триггеров.
8. **Порог переключения:** утвердить метрики и числа из §5.6 до
   начала Phase 1.

## 15. Приложение B. Минимальный пример RiveScript

```rive
! var topic = greeting

+ привет
@ greet

+ (здравствуй|добрый день|добрый вечер)
@ greet

+ почему (империя|империи) (считает|думает) (республику|республика) (незаконной|незаконная)
@ ask_reason_legitimacy

+ [а] почему *
@ ask_reason_generic

+ *
@ fallback

> topic ask_reason_legitimacy
  + *
  <call>frame intent=ask_reason predicate=consider_illegitimate agent=faction.empire patient=faction.republic theme=legitimacy</call>
< topic
```

Object macro `frame` возвращает JSON-кадр; Python проверяет его схемой.
Это иллюстрация, а не финальный синтаксис: генератор и линтер определяют
точные формы.

## 16. Приложение C. Минимальный пример продукции Soar

```soar
sp {npc*propose*eat
   (state <s> ^self <self> ^input-link <in>)
   (<self> ^needs ^hunger ^value <v>)
   (<v> > 0.6)
   (<in> ^available ^work <w> ^need hunger)
   -->
   (<s> ^operator <o> + =)
   (<o> ^name eat ^work <w> ^need hunger ^score <v>)
}
```

Числовые предпочтения и tie-break добавляются отдельными правилами;
содержание (какие работы доступны, какие веса) приходит из JSON и
перцептов, а не из этого примера.

## 17. Итог

Переход реален только как управляемая миграция, а не как «переписать всё
на Soar». Ключевые условия:

1. RiveScript отвечает за поверхность языка, Soar — за смысл и решение.
2. Python остаётся средой и единственной точкой записи состояния.
3. JSON остаётся источником истины; `.soar`/`.rive` генерируются и
   проверяются.
4. Каждая фаза имеет теневой режим, метрики, порог и откат.
5. NLU получает отдельный конвейер, линтер и золотой корпус — это самый
   рискованный и самый ценный участок.

Ближайшее действие — Phase 0 и первый спринт из §13. До завершения
Phase 1 игровое поведение не меняется.
