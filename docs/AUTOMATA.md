# AUTOMATA.md — графический редактор автоматов

> Контент-инструмент Ozvering-Project. Живёт в пакете [`automata/`](../automata),
> не импортирует `pygame` в чистой модели и не меняет канон
> `simulation.py`/`warfare.py`.

## 1. Что это и чего здесь нет

Редактор работает с **конечными автоматами как графами**: состояния (узлы),
переходы (рёбра), подписи и координаты для раскладки. Он не задаёт предметную
спецификацию — здесь нет «оружия», «техники», «ресурсов» или «диалогов» как
типов контента. Любая такая семантика может быть добавлена позже отдельным
слоем, но сам редактор остаётся структурным.

Прежний игровой цикл «Престола» из этой ветки удалён. Новый игровой цикл будет
другим и появится позже; редактор — самостоятельный инструмент, а не его часть.

## 2. Запуск

```bash
python3 main.py --automata              # редактор
python3 -m automata                     # альтернативная точка входа
python3 main.py --automata --open example  # сразу открыть пример
python3 main.py --automata --new        # новый автомат
python3 main.py --automata -f           # полный экран
```

Настройки окна (`fullscreen`) хранятся в `saves/automata/settings.json`
(каталог `saves/` в `.gitignore`). Контент — в `configs/automata/*.json` и
версионируется вместе с репозиторием.

## 3. Экран библиотеки

Библиотека показывает все `*.json` из `configs/automata/`:

* имя автомата, число состояний/переходов, дату изменения и slug файла;
* «Открыть», «Копия», «Удалить» для каждой строки;
* «+ Новый автомат» — создаёт документ с одним начальным состоянием;
* «Справка» — управление и формат файла;
* повреждённый JSON показывается отдельной строкой с ошибкой; «Открыть» и
  «Копия» для неё отключены, «Удалить» доступно;
* список прокручивается колесом, если файлов больше, чем помещается.

Удаление подтверждается модальным окном. Копия получает имя
«Копия — <исходное имя>» и новый свободный slug.

## 4. Экран редактора

```
+--------------------------------------------------------------+
| Библиотека | + Состояние | Связь | Удалить | ... | Сохранить  |
+---------------------------------------------+----------------+
|                                             |  ИНСПЕКТОР     |
|                  ХОЛСТ                      |  документ      |
|         узлы, рёбра и подписи               |  выбранный     |
|                                             |  элемент       |
+---------------------------------------------+----------------+
| статус                 подсказка                 счётчики/zoom |
+--------------------------------------------------------------+
```

### Управление

| Действие | Как |
|---|---|
| Выбрать узел/ребро | ЛКМ |
| Перетащить состояние | ЛКМ по узлу и движение |
| Панорама | ПКМ или средняя кнопка |
| Масштаб | колесо мыши (вокруг курсора), `+`/`-` |
| Добавить состояние | «+ Состояние» или двойной клик по пустому месту |
| Создать переход | «Связь» → клик по исходному, затем по целевому |
| Удалить выбранное | `Delete` / `Backspace` или кнопка «Удалить» |
| Сдвинуть состояние | стрелки; `Shift` — шаг 10 px |
| Вписать всё | `F` или «Вписать» |
| Сетка | `G` |
| Отмена / повтор | `Ctrl+Z` / `Ctrl+Y` (или `Ctrl+Shift+Z`) |
| Сохранить | `Ctrl+S` или «Сохранить» |
| Снять выбор / выключить «Связь» | `Esc` |
| Выйти в библиотеку | «Библиотека»; при несохранённых правках — вопрос |

Переходы можно создавать между любыми двумя состояниями, включая состояние и
само себя (петля). Несколько переходов между одной парой узлов рисуются со
смещением, чтобы подписи не сливались. Редактор не запрещает дубли и петли:
это структурные решения автора контента, проверка лишь предупреждает.

### Инспектор

Всегда показывает название и описание документа и счётчики. Для состояния:

* `ID` — латиница/цифры, первый символ — буква или `_`; при переименовании
  ссылки в переходах обновляются автоматически; занятый id отклоняется;
* `Название` — произвольная строка;
* флаги «Начальное состояние» (ровно одно; выбор нового снимает старый) и
  «Финальное состояние» (может быть несколько);
* входящие/исходящие переходы и кнопка удаления.

Для перехода: откуда/куда (только чтение), «Событие / подпись» и «Условие»
(оба — свободный текст), кнопка удаления.

Внизу инспектора — блок «ПРОВЕРКА»: ошибки (красные) и предупреждения
(оранжевые). Проверка не блокирует сохранение: файл можно сохранить и
исправить позже.

## 5. Модель и JSON

Один файл — один автомат. Схема (`version = 1`):

```json
{
  "version": 1,
  "name": "Простой цикл",
  "description": "Необязательное описание",
  "states": [
    {
      "id": "s1",
      "name": "Ожидание",
      "x": 120,
      "y": 160,
      "initial": true,
      "final": false
    }
  ],
  "transitions": [
    {
      "id": "t1",
      "source": "s1",
      "target": "s2",
      "event": "старт",
      "guard": ""
    }
  ]
}
```

* `id` состояния/перехода — уникальная строка; автоидентификаторы `s1`, `s2`,
  `t1`, `t2` выдаются по первому свободному номеру.
* `x`, `y` — верхний левый угол узла в мировых пикселях; размер узла на холсте
  фиксирован (172×72), масштаб меняет только отображение.
* `initial` — начальное состояние. Модель поддерживает ровно одно; файл с
  несколькими `initial` загружается, но проверка показывает ошибку.
* `final` — финальных состояний может быть несколько.
* `event`, `guard` — произвольные строки, редактор их не интерпретирует.
* Неизвестные поля при чтении игнорируются; отсутствующие `name`,
  `description`, `event`, `guard` заменяются пустыми строками.

Запись атомарная: временный файл + `os.replace`, UTF-8, отступ 2. Имя файла
(slug) образуется из названия транслитерацией кириллицы и заменой не-латиницы
на `_`; при совпадении добавляется `_2`, `_3` и т.д. Slug закрепляется за
документом при первом сохранении и не меняется при последующем переименовании
(переименовать файл можно в библиотеке через «Копию» + удаление).

## 6. Проверка структуры

`Automaton.validate()` возвращает `Issue(code, level, message)`. Коды:

| Код | Уровень | Смысл |
|---|---|---|
| `empty` | error | нет ни одного состояния |
| `duplicate_state` | error | повторяются id состояний |
| `duplicate_transition` | error | повторяются id переходов |
| `multiple_initial` | error | больше одного начального состояния |
| `missing_state` | error | переход ссылается на отсутствующее состояние |
| `no_initial` | warning | начальное состояние не выбрано |
| `unreachable` | warning | состояние недостижимо из начального |
| `dead_end` | warning | у нефинального состояния нет исходящих переходов |
| `duplicate_edge` | warning | одинаковые source/target/event |
| `no_final` | warning | нет финальных состояний |

Проверка не является «компилятором»: она помогает увидеть структуру, но не
запрещает сохранить черновик.

## 7. Архитектура

```
automata/
  model.py        # чистая модель: State, Transition, Automaton, Issue, History
  storage.py      # configs/automata/*.json: list/load/save/duplicate/delete
  canvas.py       # холст: камера, узлы, рёбра, попадания, ввод
  ui.py           # TextInput, ToolButton, ListRow, палитра холста
  app.py          # окно, шрифты, сцены, главный цикл
  scenes/
    library.py    # список файлов и действия
    editor.py     # холст + панель инструментов + инспектор
    confirm.py    # модальное подтверждение
    help.py       # справка
```

Границы:

* `model.py` не импортирует `pygame` — это проверяется тестом в отдельном
  процессе;
* `canvas.py` меняет только переданную модель и сообщает сцене о действиях
  через колбэки; история и сохранение живут в сцене;
* `storage.py` не знает о UI;
* `scenes/` переиспользуют общий каркас `ui.scene`/`ui.theme`/`ui.widgets`,
  но не зависят от `ui.app` и сохранений игры.

История — снимки `Automaton.to_dict()` (до 100 шагов). Перетаскивание узла
создаёт один шаг при отпускании мыши, а не на каждый кадр. Ввод в текстовом
поле фиксируется по `Enter`/уходу; `Esc` отменяет правку поля.

## 8. Тесты

```bash
python3 -m pytest -q tests/test_automata.py tests/test_automata_ui.py
python3 -m compileall -q automata main.py
```

* `tests/test_automata.py` — модель без pygame: id, операции, проверка,
  сериализация, история, slug, CRUD хранилища, валидность примера;
* `tests/test_automata_ui.py` — headless pygame: библиотека, новый документ,
  добавление/связывание/сохранение, инспектор, подтверждение выхода, справка.

## 9. Что можно добавить позже

Редактор намеренно не решает следующие задачи:

* несколько автоматов в одном файле и ссылки между ними;
* подсветка достижимости/циклов на холсте;
* копирование/вставка выделенной группы узлов;
* выравнивание и автораскладка;
* импорт/экспорт других форматов;
* предметные схемы (оружие, техника, диалоги) — это отдельные слои поверх
  структурного ядра.

Эти пункты не блокируют текущую работу: базовый JSON-формат и модель уже
позволяют хранить и редактировать структуру автомата.

Отдельный слой [`organizations/`](../organizations) генерирует автоматы
социальных организаций аналитически (приоритетная потребность + масштаб +
экономика участия). Готовые JSON лежат в `configs/automata/`, например
`state_fear.json`, `church_spirituality.json`, `gang_status.json`,
`trade_artel_hunger.json`; запуск — `python3 -m organizations --write`.
Спецификация — [`ORGANIZATIONS.md`](ORGANIZATIONS.md).
