# Ozvering-Project
My ideas

# Что
> **Иерархическая мультиагентная марковская игра с частичной наблюдаемостью, структурированным символьным состоянием и обучением с подкреплением.**

Стратегическая игра, где абсолютно все игровые сущности представлены в виде конечных автоматов. Автоматы основаны на IPO-архитектуре: входы, обработка, выходы, состояние. Персонажи, как частный случай автоматов, дополняются архитектурой BDI. Сущности существуют в среде, представленной как **открытая система-суперсистема** (всеобъемлющий IPO-автомат того же кодекса; §12–14 `docs/MODEL.md`). У каждой сущности две метрики: **сила** (`force`) — накопленный ресурс и целевая функция (максимизация силы), и **энергия** (`energy`) — расходуемый запас, мера способности сообщать работу.

Взаимодействие автоматов сводится к передаче энергии, в процессе которой увеличивается или уменьшается сила. Тип энергии не хранится и не конвертируется — это контекстная фаза автомата: рецептивный тип входа адресата выводится единым законом из его состояния (напор/окно/пул) и скрытой выходной фазы такта, а тип выхода — из выбранного действия адресанта. Вероятность успешной передачи и мощность зависят от входа адресанта, типа энергии и количества работы. Работа - это количество сообщаемой энергии в конкретный момент.

# Математика
Псевдокод (соответствует `simulation.py`; символы — имена кода):
```python
regen      = floor(sqrt(force))          # поток пополнения пула энергии каждый такт
energy     = pool                        # РАСХОДУЕМЫЙ запас; cap: E_MAX_MULT * regen
work       <= min(pool, MAX_WORK, max(MIN_OUTPUT, force // 4))
force      : int (вещественные приросты отдыха/трения накапливаются)
U(action)  = [delta + gamma * (reward(t)) | action]
# delta - затраты на действие, gamma - дисконт (0<gamma<1), reward(t) - изменение силы в момент t

# Восприимчивость входа адресата — триггер Шмитта с гистерезисом
# (масштабный порог, выводится из двух метрик модели — принятой работы w_adopt и силы F):
ON(F)  = max(ON_MIN, ON_FRAC * F)        # накопленное давление >= ON  => вход открыт (окно OPEN_TTL)
OFF(F) = OFF_FRAC * ON(F)                # давление упало ниже OFF     => вход закрыт
# Открытый вход: отдача работы ~ w*m*GAIN_MAX; закрытый: ~ w*m*Y_SMALL (почти нулевая).

# Логистическая прибыль покоя:
rest_gain = MAX_REST_DELTA * (E/L) * (1 - E/L),  L = L_BASE + L_STEP * rest_units
# rest_units растут ТОЛЬКО от реально полученной силы при успешных передачах.
```


# Состояние реализации (актуально)
Рабочая модель — `simulation.py`. Реализовано согласно согласованной архитектуре:
- сущности — IPO-автоматы (+BDI у персонажей), только две метрики: сила (force) и энергия (energy);
- энергия — расходуемый пул, пополняемый в такт ⌊√силы⌋ (regen); работа списывается из пула;
  формула energy = ⌊√force⌋ сохранена как поток восстановления структуры (см. «Математика»);
- тип энергии — контекстная фаза, а не хранимая валюта: не хранится и не конвертируется;
  рецептивный тип входа адресата выводится единым законом из контекста (напор/окно/пул +
  скрытая выходная фаза), тип выхода — из действия адресанта; наблюдатель усредняет по трём
  типам под равномерным (максимально-энтропийным) априором, что возвращает симметрию
  режимов (§2 MODEL.md);
- профиль (`PROFILES`) — один скаляр p ≤ 1, умножающий уже существующие константы;
  канал «ротации защиты» упразднён, автоматического назначения профиля по seed нет (§2а MODEL.md);
- восприимчивость входа адресата — триггер Шмитта с гистерезисом (масштабный порог
  ON(F) = max(ON_MIN, ON_FRAC·F)): упорное давление МОЖЕТ открыть окно, но не гарантирует;
- частичная наблюдаемость — шум наблюдения вместо шума результата;
- отдых — логистическая прибыль с потолком, растущим только от успешной работы;
- агенты: UtilityAI (утилитарный расчёт U(action)) и RLAgent (Q-learning, перенос обучения
  между партиями); условие конца — устойчивое доминирование (capture), при этом «жизнь»
  агенту гарантирована (сила не опускается ниже 1).

Эксперименты — в `experiments/` (запуск из корня репозитория); логи в репозитории не
хранятся — вывод воспроизводится запуском. Текущая воспроизводимая базовая линия
(канонический прогон, матрица баланса, ограничения) — в [`docs/BASELINE.md`](docs/BASELINE.md).
Реальный CI — [`.github/workflows/ci.yml`](.github/workflows/ci.yml) (GitHub Actions): на
каждый push/PR компилируются ядро/GUI/эксперименты и запускается `pytest`
(см. ниже). Исторические документы обсуждения — в
`docs/history/` (`ideas.md`, `simulation_v2_prototype.py`, PR-док Шмитта
`PR_schmitt_hysteresis.md`, PR-док ревью `PR_review_code_and_documentation.md` и
`REVIEW_OPEN_ISSUES.md`), помечены
статус-шапками как частично/полностью отвергнутые; канонической является механика
`simulation.py`.

# Запуск

```bash
python3 simulation.py            # канон: пакет из 10 партий + график динамики силы
python3 main.py                  # ИГРА: сценный слой ui (меню -> нарратив -> партия)
python3 main.py --scene battlefield  # сразу стратегическое поле (RTS)
python3 main.py --arena          # только АРЕНА: автономный game_engine (HUD)
pytest -q                        # весь тестовый набор (см. ниже)
```

**Единая точка запуска — `main.py`** (по умолчанию игра; `--arena` — арена;
`--fullscreen`/`-f`, `--scene NAME` — дополнительные флаги). Отдельные точки
входа тоже сохранены: `python3 -m ui` (игра) и `python3 game_engine.py` (арена).

Тесты ([`tests/`](tests/), фреймворк `pytest`):

* канон и его воспроизводимость (`test_canon.py`);
* скрипты-проверки с кодом возврата и детерминизм по `PYTHONHASHSEED`
  (`test_checks.py` → `exp_balance_ci.py`, `exp_hierarchy_depth.py`,
  `exp_retaliation_faithful.py`, `exp_domain_invariance.py`);
* согласованность «доки ↔ код»: константы `docs/MODEL.md §8` и ссылки на
  эксперименты (`test_docs_sync.py`);
* сторож доменной инвариантности ядра (F1): в ядре взаимодействия нет доменной
  ветки (`test_domain_audit.py`);
* новые слои: энтропия смысла, лоссовая наблюдаемость, LOD
  (`test_advanced.py`: детерминизм, монотонность `H`, «нет отката», гистерезис,
  квантование/задержка, LOD-эквивалентность, флаги off = канон);
* сценный слой `ui/`: сохранения/настройки, навигация и отрисовка экранов
  (`test_ui.py`; графическая часть пропускается без `pygame`); чистая логика
  стратегического поля — `test_battlefield.py` (изометрия, приказы, диалоги).

Скрипты-проверки можно запускать и напрямую (код возврата `0`/`1`):

```bash
python3 experiments/exp_balance_ci.py            # баланс стратегий (недоминирование)
python3 experiments/exp_hierarchy_depth.py       # самоподобие кодекса на всех ярусах
python3 experiments/exp_retaliation_faithful.py  # верность оценки возмездия (A3)
python3 experiments/exp_sensitivity_f2_f3.py     # F2/F3/C1: чувствительность констант
python3 experiments/exp_g1_keffect_window.py     # G1: окно K_EFFECT (N=12 + N=40)
python3 experiments/exp_g2_profiles.py           # G2: профили p<1 и их компенсации
python3 experiments/exp_p1_rl_boost.py           # P1: потолок табличного RL
```

Зависимости: рантайм — `pip install -r requirements.txt` (графики, эксперименты,
графический движок); тесты — `pip install -r requirements-dev.txt` (только `pytest`).
Чек-лист ревью — в [`.github/pull_request_template.md`](.github/pull_request_template.md);

# Графический слой (экраны и наблюдение за партией)

Игровая оболочка — **сценный 2-D слой** [`ui/`](ui): главное меню, настройки,
сохранения/автосохранения, нарративные экраны и игровое поле. Единая точка запуска —
`python3 main.py`. Требуется `pygame-ce` (рекомендуется — корректные шрифты и кириллица):

```bash
pip install pygame-ce
python3 main.py               # игра (старт — главное меню)
python3 main.py --fullscreen  # полноэкранный режим
python3 main.py --arena       # арена отдельно (то же, что game_engine.py)
```

`game_engine.py` — слой «основное игровое поле» (арена + HUD дуэли `RLAgent` против
`UtilityAI` в среде-автомате, ручной режим управления RL-агентом), используемый сценным
слоем как экран `game`; запускается и автономно (`python3 game_engine.py`). Выход из
арены: клавиши `ESC`/`Q` **или клик по кнопке `QUIT` в HUD** (мышью — всегда).

Сценный слой также содержит **пошаговое стратегическое поле (RTS)**: изометрическая сетка
11×9, выбор юнита, приказы движения/давления, контакт, очки команд, высота и
ролевые диалоги командира. Логика — `ui/battlefield.py` (без pygame), экран —
`ui/scenes/battlefield.py`; бой считается `simulation.run_tick`, поэтому канон
не меняется. Запуск: «Поле боя (RTS)» в меню или `python3 main.py --scene
battlefield`. Ассеты пока — плейсхолдеры `[ IMG: ... ]` / `[ PORTRAIT: ... ]`.

Оба слоя используют **только публичное API** `simulation.py` (модель не изменяется);
арность `RLAgent.form_intention` определяется авто-детектом, поэтому движок совместим
с текущей ревизией (проверено прогоном `MatchEngine` без графики). Сохранения и
настройки — в `saves/` (в репозиторий не попадают). Подробности сценного слоя —
[`docs/UI.md`](docs/UI.md), история движка — [`GAME_ENGINE_CHANGES.md`](GAME_ENGINE_CHANGES.md).

Подробная документация механики, формул, параметров калибровки и протокола такта — в [`docs/MODEL.md`](docs/MODEL.md). В коде сохранены только docstrings (что делает функция/метод); пространные пояснительные комментарии вынесены в документацию для читаемости.

Краткая выжимка по всему проекту (онтология, законы, слои, статус) — [`docs/SUMMARY.md`](docs/SUMMARY.md).

# Новые слои (MVP, выключены по умолчанию)

Три доработки вкатаны флагами **off**, поэтому канон `run_batch(10)` остаётся
`RL 1 / UtilityAI 9 / no capture 0`:

* **лоссовая агрегация** — `play_game(..., lossy=True)`: суперсистема видит
  агрегат `Observation` (без identity/типа/тайминга), части — только публичное
  окно с задержкой (`observability.py`; снимает двойное нагружение F5);
* **LOD** — `lod.run_duel_lod`: LOD-1 событийный, LOD-2 работа + аналитическая
  интеграция времени, LOD-3 mean-field с областью валидности и fallback
  (`lod.py`; канон `play_game` — LOD-1);
* **энтропия смысла** — `play_game(..., entropy=True)`: `H` по 4 корзинам
  убеждений, `H_cum`-ratchet + lineage, тяжёлохвостый мультипликативный шум
  только на `beliefs`, демпфер опциона `1 - noise_floor` (`information.py`).

Решения, границы MVP и открытые задачи — [`docs/DESIGN_ADVANCED.md`](docs/DESIGN_ADVANCED.md).
